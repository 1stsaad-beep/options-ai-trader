## خط الأساس والزيادة

بعد استعادة المصدر الأصلي وإثبات سلامة ZIP، شُغّل خط أساس V0.3 فعليًا: **121 ناجحًا، صفر فشل، صفر تجاوز** في 1.21 ثانية؛ الدليل `restored-v03-baseline.xml`. اختبارات V0.2 التسعة والأربعون جزء من تاريخ التغطية، وليست نتيجة إضافية تُجمع مع المجموع الحالي.

V0.4 يضيف 64 حالة Python: 23 في `test_automation_v04.py`، و36 في `test_adversarial_v04.py`، و5 في `test_api_v04.py`. المراجعة المستقلة ذات 36 حالة شُغّلت أيضًا منفردة ونجحت؛ دليلها `docs/evidence/v04-independent-security-tests.xml`، وهي جزء من 185. Flutter ارتفع من 15 إلى 24 اختبارًا: 11 API و13 widget.

ظهر تحذير واحد غير فاشل في Python: Starlette يحذر من مسار TestClient المستخدم مع httpx ويقترح httpx2. أبقينا الاعتماديات المثبتة والمتوافقة مع الاختبارات الحالية؛ هذا التحذير ليس خطأ تنفيذ ولم يُخفَ. تحديثه يحتاج فحص توافق منفصل.

## السيناريوهات التي نُفذت

- توليد دخول Call وPut من قواعد كمية فعلية، ثم اختيار عقد وفحص المخاطر والتنفيذ على دفتر Mock.
- تعطيل الأتمتة افتراضيًا، رفض Live والوسطاء الخارجيين، وقفل التنفيذ خارج paper/mock، بما فيه تنفيذ إغلاق مقبول سابقًا بعد تغيير الوضع.
- طلبات مكررة وفقدان الرد والتزامن ومعرّفات تنفيذ مكررة؛ دورة واحدة لكل ملاحظة دون زيادة تعبئة جزئية أو إنشاء أمر ثانٍ.
- تزامن دورات من اتصالين SQLite مستقلين، وحجز بيع لا يتجاوز الكمية المملوكة.
- التنفيذ الجزئي، إلغاء بقية الشراء عند الخروج، وقف الخسارة، جني الربح، إغلاق جزئي واستكماله وإعادة تسعيره، وإعادة التشغيل والمصالحة دون إعادة الإرسال.
- انقطاع الحساب أو السوق، قدم الأسعار أو مستقبلها أو تناقضها، فساد الدفتر والإعدادات، وعدم استعادة الثقة تلقائيًا.
- انتهاء عقد وتسوية تحفظية مرة واحدة فقط بعد مصالحة موثوقة، مع عزل الحسابات.
- حدود الخسارة اليومية والتعرض والحساب والمجموعات والمشرف العالمي؛ إغلاق المملوك أثناء الإيقاف الطارئ وفق القيود.
- فشل الذكاء الاصطناعي وغياب سلطته على التنفيذ، ومنع حقن أسعار أو أوامر أو تجاوزات عبر واجهة دورة الأتمتة.
- HTTP فعلي محلي يتحقق من المصادقة وعزل الحسابات والدخول الآلي الجزئي والإغلاق وعدم إعادة الدخول، إضافة إلى تشغيل العامل المستقل.
- Flutter: اتصال الحساب الصحيح، رفض نتائج لحساب أو مصدر آخر، عدم إعادة محاولة الطفرات تلقائيًا، عزل إعدادات الأتمتة ونتائج الدورات، وحدود الواجهة وLive المقفل.

## محاسبة تاريخية دون ادعاء ربحية

التجربة المصطنعة أُعيد تشغيلها: رصيد بداية 10,000، رصيد نهاية 9,973.40، خسارة 26.60، وعمولات إجمالية 2.60، مع السبريد والانزلاق. الإشارة يحقنها السيناريو لاختبار توقيت التنفيذ والمحاسبة؛ `profitability_evidence=false`. اختبارات المحرك تمنع التسرب المستقبلي، لكن لا توجد دراسة تاريخية مستقلة خارج العينة على بيانات خيارات حقيقية.

العرض الآلي ذو أربعة سيناريوهات يستخدم أسعارًا مضبوطة للجني والخسارة والانتهاء والانقطاع. أرقامه ليست أداءً استثماريًا. دفتر الأتمتة يطبق bid/ask والسبريد، ولا يضيف عمولات وانزلاقًا إضافيين في V0.4.

## إعادة التشغيل

```sh
python -m pytest -q backend --junitxml=backend-tests.xml
python scripts/smoke_http.py
PYTHONPATH=backend python scripts/demo_lifecycle.py
cd mobile
flutter analyze
flutter test --machine > flutter-tests.json
flutter build apk --debug --build-name=0.4.0 --build-number=4
```

يتطلب ذلك تثبيت اعتماديات README وSDK المناسب. `docs/BUILD_V04.md` يوضح ظروف البناء وأدواته. أي محاولة بناء تعثرت أثناء استعادة الاعتماديات ليست نجاحًا؛ يعتمد تسليم APK على نتيجة التجميع النهائية والتحقق من الملف نفسه.
