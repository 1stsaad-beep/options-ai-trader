# Observed strategy parity and prefix comparison — batch24

`observed-market-strategy-v1` now names the same five Direct rules on Python and Dart: trend, range/volume breakout, mean retest with price structure, newly confirmed regular divergence with a structure break, and confluence. The signal module is separate from chart widgets. Existing synthetic server/Demo strategies retain their original contracts; this does not relabel old decisions or complete all wave/engine/Demo parity.

All ordering comparisons use a relative `1e-9 * max(1, abs(a), abs(b))` dead band to avoid Python/Dart floating-point tie divergence. Strict breaks inside that band are not confirmed; inclusive RSI/retest/volume bounds include a numerical tie. New Direct receipts name the strategy contract, while original receipts remain unchanged. Quote qualification, session/expiry, account ownership, optional analysis failure isolation and risk admission still decide whether a signal can create a virtual fill.

Every prefix compares all five complete signal results across runtimes, including Call/Put trend, breakout, pullback, regular-divergence structure breaks, flat/warmup and volume rejection. These are synthetic test inputs, not market sessions or profitability evidence. Python's 32 new tests also cover immutable input, numeric tie thresholds, malformed/future/duplicate/non-minute bars and an authenticated no-write/no-provider endpoint. Flutter acceptance remains pending for this batch.

The saved-decision view adds a separate optional comparison of the five current rules, using only bars through the selected cursor. A verified complete source window is required; no chart is fabricated for a missing/tampered archive. Original decision JSON, reasons, balances and fills are not modified. An older cursor never displays the original final decision snapshot. Comparison output explicitly denies execution and P&L and does not attest that historical bars had already been received at an earlier cursor.

`POST /api/research/strategy-comparison` exposes the identical bounded calculation with API authentication and the existing 128KiB request cap. Input contains account label, symbol, source (`fixture`/`alpaca`), capture time, original one-minute bars and cursor; at most1000 bars and supported finite numeric magnitudes are accepted. The endpoint neither imports a device account into the server nor reads a provider or writes the ledger. Client evidence remains unverified. This closes a portable alternative-signal comparison, not option-outcome backtesting, server/device ledger synchronization, persistent market-priced execution, or a complete strategy tournament.
