# الأرشفة طويلة المدى — migration8

استُبدل حد الحساب1000 مشاهدة/64MiB بمقاطع: كل مقطع يستوعب حتى1000 مشاهدة أو64MiB، ثم يُغلق ويبدأ مقطع جديد في المعاملة نفسها. لا تُحذف أو تُعدل المشاهدات الأصلية. migration8 يبني فهرس المقاطع من السجلات الموجودة دون تغيير payload أو digest أو recorded_at. المقاطع المغلقة محمية من التعديل والحذف. تظل المشاهدة الواحدة محدودة بـ2MiB.

هذا تخزين append-only في PostgreSQL/SQLite مع تصدير مستقل، وليس حذفًا تلقائيًا للبيانات القديمة أو تخزينًا سحابيًا أو WORM. نمو قاعدة البيانات يحتاج مراقبة مساحة القرص ونسخًا مستقلة. لا حد إجمالي مصطنع1000/64MiB بعد الترقية؛ السعة الفيزيائية ليست غير محدودة. فشل الكتابة يتراجع عن المشاهدة وفهرسها معًا. API يعرض عدد المقاطع والسجلات والبايتات.

## التصدير والتحقق

الأداة محلية للمشغل، لا تستقبلها واجهة الهاتف ولا تفتح اتصال سوق. يُمرر اتصال DB عبر `DATABASE_URL` الخاص خارج Git، ولا تُكتب قيمته في المحادثة أو سجل الأوامر. التصدير يثبت لقطة متسقة ويكتب JSONL تدريجيًا دون تحميل الأرشيف كله في الذاكرة. يحتفظ بـ:

- كل المشاهدات للحساب، بنص payload وبصمته وتسلسله وتوقيته الأصلي.
- أحداث Market Runtime الأصلية وبصماتها، وإقرارات قراءة التنبيهات.
- audit الخاص بحفظ مشاهدات السوق.

لا تُصدَّر مفاتيح أو SQL أو صلاحيات تنفيذ أو أموال/مراكز Demo. النسخة الكاملة لقاعدة البيانات ما زالت مطلوبة لحماية هويات الحسابات والدفاتر والإعدادات. التصدير يجمع **تاريخ الحساب كله**؛ المقاطع فهرسة داخل DB وليست حذفًا بعد التصدير. النسخ المتتابعة قد تتداخل، والاستعادة تزيل التكرار بالمطابقة الدقيقة لا بتغيير الأصل.

```bash
python scripts/market_archive.py export /secure-backups/account-market.jsonl --account-id ACCOUNT_UUID
python scripts/market_archive.py verify /secure-backups/account-market.jsonl --sha256 VERIFIED_SHA256
```

ملف جديد فقط بصلاحيات0600؛ يُرفض استبدال ملف موجود. يحسب التحقق SHA-256 لكل الأصل ومجموع الملف، ويسجل أعداد الجداول ونهاية موثّقة. الملف المبتور/المعدل/الإضافات بعد نهايته/الرموز المستقبلية بالنسبة للقطة/التسلسل الناقص تُرفض. الفشل يترك ملفًا غير صالح للتحقق بدل حذف السجلات. التصدير الكبير يَحجز الكتابات أثناء تثبيت اللقطة؛ نفّذه في نافذة صيانة مناسبة، ولا تدّعِ أنه تصدير بلا أثر على latency. SHA-256 ليس تشفيرًا أو توقيع هوية المُصدر: انقل النسخة إلى تخزين خاص مشفر خارج الجهاز واحتفظ ببصمتها في قناة مستقلة موثوقة.

## الاستعادة دون فقد أو إعادة تشغيل التحليل

1. تحقق من النسخة ومصدرها الموثوق. استعد أولًا نسخة قاعدة البيانات إلى هدف جديد بأدوات PostgreSQL الحالية عند فقد قاعدة البيانات؛ يحتاج الأرشيف إلى **هوية الحساب الأصلية نفسها** ولا يصنع حسابًا أو رصيدًا بديلًا.
2. عطّل تحليل Market Runtime لذلك الحساب. لا يوجد import HTTP، ولا يُسمح بالاستعادة لحساب enabled.
3. شغّل على الهدف المختار:

```bash
python scripts/market_archive.py restore /secure-backups/account-market.jsonl \
  --account-id ACCOUNT_UUID --sha256 VERIFIED_SHA256 --trusted-project-archive
```

4. الاستعادة معاملة واحدة: تحفظ الأصول حرفيًا، وتضيف المفقود فقط، وترفض أي تعارض في السجل/الحساب/المفتاح. فشل متأخر أو تغير الملف أثناء القراءة يتراجع عن كل الإضافات. التكرار يعطي صفر إضافات؛ لا حذف أو overwrite. يبقى التحليل معطلاً، ولا تتغير المراكز أو الأوامر أو مخاطر Demo.
5. يُحفظ recorded_at الأصلي؛ الاستيراد لا يزعم أن بيانات التاريخ كانت متاحة وقت السوق. replay يبقى مقيدًا بالحساب ووقت الإتاحة. لا يُملأ cache الحالي بأسعار قديمة ولا تُصنع تعبئات عند الاستعادة. راجع الأصل عبر observations API، ثم أعد تشغيل التحليل بصورة صريحة عند الحاجة وبعد موافقة الاتصال المنفصلة.

## التحقق

الاختبارات المستهدفة تشمل تسجيل1003 مشاهدات، وتجاوز64MiB فعليًا، وإغلاق المقاطع دون حذف، وتصدير/استعادة حرفية، وتكرار الاستعادة، وتعارض متأخر، وملف يتغير أثناء الاستعادة، وعزل الحسابات/الصلاحية وrollback فشل كتابة الفهرس. أُضيفت بوابة PostgreSQL لاستعادة مشاهدات تم التقاطها **بعد** النسخة الكاملة، مع الحفاظ على الأصل السابق والدفتر والمخاطر. النتائج الفعلية النهائية وروابطها في تقرير تسليم Build18 وPROGRESS.
