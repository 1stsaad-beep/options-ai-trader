# Optional device archive isolation — batch26

Root format `paper-independent-manifest-v2` separates the financial ledger/receipt journal from `waveArchive`, `optionArchive` and `barArchive`. Each is content-addressed in a separate physical directory. All chunks and parent-directory entries are synced before the AtomicFile root is published. No original chunk or legacy anchor is deleted. Legacy raw/v1 ledgers retain a lossless anchored copy during their first v2 write.

A lossless JSON template replaces only top-level optional values with null placeholders. Original field order, whitespace, escaped Unicode, exponent notation and floating-point lexemes survive restoration exactly. Re-encoding via JSONObject would silently change1.0 to1 and could invalidate stored OHLCV source hashes, so that is deliberately avoided. Duplicate root fields and excessive nesting are rejected.

Financial chunk corruption still blocks the ledger. Missing/corrupted optional chunks yield explicit `paper-optional-archive-v1` unavailable markers bound to the original manifest hash. Writing financial changes retains those exact original references and damaged files; it does not substitute an empty archive. Markers cannot be imported from an unrelated source or repointed. Full backup export still refuses unavailable chart-source joins, rather than claiming that missing history was backed up.

If an optional chunk becomes unavailable while the Dart controller is already running, the preimage check distinguishes that physical availability change from a financial change. It discards the current uncommitted attempt, refreshes only the optional markers and stays available for a fresh quote/retry. The next protective attempt can save its actually available inline chart source. Any concurrent financial mutation or ordinary/malformed archive edit still locks CAS. No fill is accepted using a stale retry.

Eight JVM cases cover exact bytes/Unicode, missing and damaged optional chunks, preservation through financial writes, immutable archive reuse, corruption of financial chunks, forged pointers, interrupted staging and invalid templates. Three Flutter regressions cover live optional loss, fresh protective retry and concurrent-owner rejection. An additional real Android instrumentation case exercises AtomicFile/CAS after optional loss, with no actual provider calls. These new-source gates are pending CI; instrumented APK packaging remains deferred until final software closure per the approved workflow.

Remaining limits are explicit:64MiB logical device ledger,16MiB full backup, full-memory bridge/validation, finite archive caps and append storage without garbage collection. Optional new-capture write failure under genuine disk exhaustion can still prevent a whole transaction; reserved capacity/separate capture commit and bounded streaming/export remain follow-up work. This batch isolates existing optional physical corruption; it does not claim unlimited storage, a phone soak, iOS native isolation, or final product acceptance.
