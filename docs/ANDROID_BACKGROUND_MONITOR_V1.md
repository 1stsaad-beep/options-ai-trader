# مراقبة Android في الخلفية — تجربة محدودة

الخيار الجديد يقرأ حالة خادم Market Runtime فقط. ليس نقلًا لمحرك Python/قاعدة البيانات إلى الهاتف. التحليل وإعداداته لكل حساب والأرشيف يبقون على الخادم؛ يمكن استعمال Linux لاحقًا دون شراء خدمة الآن. لا Alpaca/IBKR ولا أوامر أو صلاحية اتصال مزود في هذا الخيار.

من «خادم السوق» افتح زر «مراقبة Android التجريبية». اختر حساب الخادم، راجع التنبيه وابدأ جلسة يدويًا، ثم اسمح بالإشعارات. HTTPS مطلوب حتى للشبكة المحلية في هذا الخيار؛ الاستثناءات المحلية لواجهة التطبيق العادية لا تنتقل للخدمة. ترفض الخدمة روابط المزود ومسارات/حسابات غير صالحة وإعادة التوجيه. رمز API يمر في الذاكرة فقط، لا في Intent أو إعداد دائم أو سجل، ولا توضع مفاتيح وسيط داخل APK.

مدة الجلسة القصوى30 دقيقة، وقراءة GET واحدة كل دقيقة تقريبًا إلى status للحساب المختار. تعرض الخدمة إشعارًا ثابتًا عامًا مع زر إيقاف دون أسعار أو رصيد أو أسماء حسابات على شاشة القفل. تُتحقق هوية الحساب وschema وكل أعلام قفل التنفيذ قبل اعتماد النبض؛ نجاح API ليس اتصال Alpaca ولا صلاحية تنفيذ أسعار الخيارات. الأحداث التفصيلية تبقى في صندوق API؛ هذه ليست Push لكل حدث.

الانتقال إلى الشاشة الرئيسية يسمح باستمرار المحاولة. انقطاع الإنترنت يعرض حالة تعذر تحقق؛401/403 يوقف الجلسة. إيقافها لا يغيّر إعداد التحليل على الخادم. تغيير حساب الشاشة أو عنوان/رمز اتصال الخادم يوقف المراقبة أولًا. لا جلسات متعددة ولا تبديل تلقائي للحساب، ولا إقرار قراءة/تعديل config في الخلفية.

**لا تشغيل والهاتف مطفأ.** إزالة مهمة التطبيق أو Force Stop أو إعادة التشغيل تفقد الجلسة؛ يجب تشغيلها يدويًا من جديد. لا BOOT receiver أو START_STICKY أو wake lock أو استثناء تلقائي لتوفير الطاقة. قد يؤخر Doze القراءات أو يقتل النظام/الشركة المصنّعة العملية؛ المدة والتردد حدان هندسيان وليسا ضمان توقيت. يعالج التطبيق onTimeout بالإيقاف ويحد جلسته بنفسه.

وثائق Android الرسمية التي روجعت2026-10-12: [قيود بدء Foreground Service](https://developer.android.com/develop/background-work/services/fgs/launch)، [حدود dataSync ومعالجة المهلة](https://developer.android.com/develop/background-work/services/fgs/timeout)، [إذن الإشعارات](https://developer.android.com/develop/ui/compose/notifications/notification-permission). Android15+ يفرض حدًا إجماليًا على dataSync أثناء الخلفية؛ لا يجوز استعمال هذه التجربة كضمان عمل24/7.

## اختبار قبول الهاتف — لم يُنفذ على جهاز هنا

1. ثبّت Lab19 بجانب Lab18 وما قبله؛ لا حذف أو Clear Data، ولا استيراد Demo تلقائي. تحقق أولًا من بقاء النسخة القديمة وبياناتها.
2. استخدم خادم اختبار تملكه، provider معطل، حسابين منفصلين وHTTPS موثوقًا. ارفض الإشعارات: لا تبدأ خدمة. اسمح بها من الإعدادات وأعد البدء يدويًا.
3. تحقق من الإشعار وزر الإيقاف؛ غادر إلى Home، اقفل الشاشة وأعد فتحها، وراجع last check وحداثة النبض. سجل طراز الهاتف وإصدار Android وإعداد البطارية والفترات الفعلية.
4. اقطع الإنترنت ثم أعده؛ لا يُعرض نجاح قديم. جرّب توكن اختبار مرفوضًا: تتوقف الجلسة، دون تكرار طلبات التعديل أو أي اتصال وسيط.
5. بدّل الحساب أو اتصال الخادم: تتوقف الجلسة القديمة؛ لا تستقبل استجابة حساب آخر ولا تتحول تلقائيًا. إعدادا تحليل الحسابين يبقيان مستقلين على الخادم.
6. انتظر انتهاء30 دقيقة، ثم جرّب إزالة المهمة وForce Stop وإعادة تشغيل الهاتف. لا بدء خفي بعد أي منها، ولا ادعاء استمرار عند إطفائه. جرّب أيضًا رفض قناة الإشعار وحد Android على جهاز اختبار.
7. قارن قاعدة Demo والنسخة القديمة قبل/بعد؛ لا تغييرات مالية. تحقّق من مصدر الخادم مستقلًا عن هذه الواجهة.

اختبار سياسة Java وFlutter mocks وبناء APK لا تعوض هذه الاختبارات الفعلية. Linux المستقل يحتاج لاحقًا اختبار استمرارية، مساحة ونسخ مشفرة خارج المضيف ومراقب انقطاع. التوقيع الحالي تطويري مؤقت، فلا وعد بترقية APK فوق النسخة ذات الهوية نفسها.
