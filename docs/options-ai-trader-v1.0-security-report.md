# Options AI Trader — تقرير الأمان V1.0 RC1

تاريخ الفحص: 2026-10-10. النطاق: مصدر المشروع المستعاد من V0.5، إضافة V1، دفتر Mock، Demo المحلي، API، ملفات CI. ليس اختبار اختراق مستقلًا ولا اعتمادًا ماليًا.

## ضوابط مستمرة

- Live مقفل في إعدادات الخدمة والتطبيق ومحولات الوسطاء. لا اتصال IBKR، حتى Paper، ولا شبكة أو أوامر مالية من Demo المحلي.
- Generic Analysis Adapter معطل. لا استدعاء لمشروع خارجي أو API مدفوع، ولا مفتاح وسيط مطلوب في المحادثة.
- المحركات البحثية لا تملك مراجع تنفيذ أو تعديل مخاطر؛ الدرجة التشخيصية لا تتجاوز شرط أمان إلزاميًا.
- المستودع خاص، وV1 على فرع مستقل. لا مفاتيح توقيع أو كلمات مرور إنتاجية في الملفات المطلوب تسليمها.

## فحص الأسرار والاعتماديات

شُغّل فحص أنماط المصدر والتاريخ بواسطة `scripts/security_scan.py`. المصدر الجاري لم يتضمن مطابقات مشتبهًا بها وقت الفحص. الفحص المحلي لكل التاريخ وجد ست مطابقات في **نسخة تاريخية من تقرير JUnit**: أسماء اختبارات احتوت سلاسل اختبار مصطنعة لكاشف الأسرار، ومنها عنوان مفتاح خاص بلا مفتاح فعلي. روجعت باعتبارها fixtures، وعدلت أسماء الاختبارات كي لا تتكرر في التقرير الحالي؛ لم يُعد كتابة تاريخ Git أو حذف تقرير قديم.

الفحص نمطي، لا يثبت خلو المشروع المطلق من أسرار. يعلن الملفات الثنائية والأرشيفات غير المفكوكة والملفات الكبيرة المتجاوزة؛ لا يفحص `.bundle` تلقائيًا من الداخل. التاريخ المحلي المستعاد فُحص منفصلًا قبل أرشفته. لا توجد محاولة لاختبار صلاحية أي سلسلة لدى مزود خارجي.

شُغّل `pip-audit` على `backend/requirements.lock`، وOSV على الإصدارات الدقيقة للحزم المستضافة في `mobile/pubspec.lock`. لم يجد التشغيل الموثق ثغرات معروفة في 24 اعتماد Python و43 حزمة Dart مستضافة. حزم Flutter SDK مستبعدة صراحة من استعلام Pub. هذه نتيجة قواعد الثغرات المعروفة في وقت الفحص، ولا تغطي كل اعتماد Gradle/Android/iOS أو صورة حاوية أو منطق التطبيق. راجع JSON في `docs/evidence/v1/` ونتيجة CI النهائية في تقرير الاختبارات.

## التوقيع والأذونات

مفتاح تطوير V0.5 غير موجود في الملفات المستعادة؛ لا يمكن استرجاعه من شهادة عامة. النسخة القابلة للتثبيت عند غياب Secrets هي Preview بمعرف حزمة منفصل وتوقيع تطوير مؤقت يحققه `apksigner`. هذا لا يوفر سلسلة ترقيات بتوقيع ثابت بين تشغيلات CI. المعالجة المتبقية: تخزين مفتاح تطوير خاص ثابت ونسخة احتياطية مشفرة عبر GitHub Actions Secrets الأربع في `DEVELOPMENT_SIGNING.md`، دون وضع المفتاح في Git أو المحادثة. التكوين الجزئي للأسرار يفشل بدل استخدام بديل صامت.

البناء debug وقابل للتصحيح ويسمح باتصالات HTTP في وضع التطوير عند اختيار Backend يدويًا؛ لا تستخدمه لنقل رمز أو بيانات حساسة عبر شبكة غير موثوقة. Demo الافتراضي بلا شبكة. البناء غير صالح لتوزيع متجر أو بيانات مالية حساسة. البناء iOS غير الموقع، إن نجح، ليس IPA قابلًا للتثبيت أو TestFlight. لا حساب Apple مدفوع أو شهادة مستخدمة في هذه المهمة.

## المخاطر والحدود المتبقية

- النظام لمالك واحد، بمفتاح Bearer محلي؛ لا RBAC/MFA أو سياسة جلسات متعددة المستخدمين. المصادقة وعزل حسابات التداول وظيفتان مختلفتان.
- محدد معدل الطلبات داخل العملية فقط؛ يحتاج ضبطًا مشتركًا أو بوابة آمنة قبل تعدد نسخ الخدمة. لا تعرض API أو قاعدة البيانات للإنترنت اعتمادًا على إعداد التطوير.
- أقفال Mock والقيود واللقطات لا تحمي من مدير قاعدة بيانات خبيث، ولا من وسيط يعيد بيانات غير صحيحة. لا يوجد تحقق خارجي فعلي.
- النسخ الاحتياطية غير مشفرة داخل الأداة وmanifest غير موقع. استعادة PostgreSQL وتدوير الأسرار والإجراءات التشغيلية الممتدة لم تُعتمد.
- حسابات الوقت والسيولة والانتهاء والوقف تقريبية. إشارة وقف ليست سعر تنفيذ مضمونًا؛ انقطاع بيانات السوق يوقف التنفيذ ولا يضمن تصفية.
- محركات Shadow والتجارب الاصطناعية ليست أساسًا لتفعيل Live. لا قياس ربحية خارج العينة ببيانات سوق مرخصة.
- لم يُجرَ فحص اختراق خارجي أو اختبار جهاز محمول حقيقي أو تدقيق سلسلة توريد شامل. التقرير يذكر حالات الاختبار الفعلية وحدها.
