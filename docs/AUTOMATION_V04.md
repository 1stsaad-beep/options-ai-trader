# V0.4 — دورة التنفيذ الآلي التجريبي

هذه الدورة تستخدم بيانات مصطنعة ودفتر MockBroker المحلي فقط. لا تتصل بوسيط أو مزود تحليل، ولا تتيح التداول الحقيقي. القيمة الافتراضية لكل حساب هي `automation_enabled=false`، ويستمر العامل العادي في تسجيل التحليلات فقط.

## المسار المنفذ

1. تفعيل صريح لحساب `paper/mock`، مع قائمة مراقبة متحققة داخل كتالوج Mock ومفعلة.
2. رفض حالة حساب مجهولة أو أقدم من 120 ثانية. بدء تشغيل Repository جديد يعيد الحسابات إلى حالة غير موثوقة، وتلزم مصالحة صريحة.
3. قفل معاملة قاعدة البيانات طوال الدورة؛ قفل SQLite أو قفل PostgreSQL الاستشاري القائم يشمل الحسابات وحدود المخاطر المشتركة.
4. تدقيق دفتر الأوامر والتنفيذ والرصيد والمراكز، ثم مصالحة الحساب الموثوق فقط. لا تستطيع الدورة تصحيح اتصال مقطوع أو اعتماد حالة مجهولة تلقائيًا.
5. معالجة انتهاء العقود للحساب نفسه وفق السياسة التحفظية: خسارة كامل التكلفة، دون ممارسة أو تعيين أو إنشاء أمر مالي. تتطلب المعالجة حسابًا موثوقًا، ولا تحتاج اختلاق سعر سوق.
6. تقييم المراكز المملوكة أولًا. إذا بلغ سعر العرض `bid` وقف الخسارة أو جني الربح نسبةً إلى متوسط تكلفة المركز، تُلغى كمية الشراء غير المنفذة للعقد نفسه ثم يُرسل أمر `SELL_TO_CLOSE` بالكمية المتاحة غير المحجوزة.
7. استكمال الأوامر الآلية الجزئية. يتقدم التنفيذ بجزء واحد لكل أمر ولكل توقيت ملاحظة أسعار جديد.
8. تحليل شموع مكتملة سببية باستخدام القواعد الكمية الفعلية `breakout/pullback`، ثم ترتيب الفرص واختيار عقد Call أو Put واحد وفق الصلاحية والعمر والسبريد والدلتا والسيولة التجريبية.
9. إرسال أمر شراء محدود عبر `TradingService`؛ محرك المخاطر القائم يعيد فحص حدود العقد والقسط والتعرض والخسارة اليومية والحساب والمجموعة والمشرف العام.
10. محاكاة الشراء عند `ask` والإغلاق عند `bid` داخل دفتر التنفيذ نفسه. قبل **كل إرسال وتنفيذ** تعاد مصالحة الحساب الموثوق والتحقق من صلاحية الأسعار وملاحظة السوق وفق الوقت الحالي.

الأوامر والتنفيذ والتدقيق ضمن معاملة واحدة؛ لا تُحفظ نصف دورة إذا وقع خطأ غير معالج. أخطاء الرموز المحلية تسجل سبب المنع، وأخطاء الدفتر تسجل منعًا وتثبت قفل الحالة غير الموثوقة بعد التراجع. الحساب ذو إعدادات تالفة لا يوقف فحص الحسابات الأخرى أو إغلاق مركز موثوق في حساب مستقل؛ يبقى فتح تعرض جديد خاضعًا لسلامة المخاطر العامة.

## إعدادات مستقلة لكل حساب

| الحقل | الافتراضي | المدى |
|---|---:|---:|
| `automation_enabled` | `false` | قيمة Boolean فعلية |
| `stop_loss_pct` | 20 | 1–95 |
| `take_profit_pct` | 30 | 1–500 |
| `auto_quantity` | 1 | 1–100، وتظل حدود المخاطر والعقود نافذة |
| `auto_fill_chunk` | 1 | 1–100، ويُقص بالكمية المتبقية |
| `max_spread_pct` | 10 | 1–50 |

تفعيل الأتمتة لحساب يعني إدارة **جميع مراكزه التجريبية المملوكة**، بما فيها المراكز المفتوحة يدويًا. الأوامر اليدوية لا ينفذها العامل تلقائيًا؛ الاستثناء هو إلغاء الجزء الباقي من شراء يدوي عند خروج آمن من المركز نفسه. البادئتان `auto-e:` و`auto-x:` محجوزتان داخل خدمة التنفيذ، ولا تقبلهما أوامر API اليدوية.

الكمية المطلوبة لا تُخفض سرًا لتجاوز رفض المخاطر: مثلًا شراء عقدين بسعر 1.05 دولار في حساب تجريبي بقيمة 10,000 دولار يتجاوز حد القسط الافتراضي 2%، فيُرفض. يمكن استخدام عقد واحد أو تغيير رأس المال التجريبي والإعدادات ضمن حدود الخدمة للاختبار.

## منع التكرار والانقطاع

- مفتاح الدخول مشتق من الحساب والرمز وتاريخ UTC. يوجد **دخول آلي واحد كحد أقصى لكل رمز في الحساب في اليوم**، حتى بعد إغلاقه؛ هذه سياسة V0.4 تحفظية قابلة للمراجعة مستقبلًا.
- مفتاح التنفيذ مشتق من الحساب والأمر وتوقيت سعر الخيار. تكرار الدورة أو فقدان الرد أو تغير محتوى سعر يحمل التوقيت نفسه لا يستهلك جزء تنفيذ ثانٍ.
- مفتاح الخروج يشمل هوية العقد وآخر تسلسل شراء منفذ وتوقيت السعر؛ إعادة فتح العقد يدويًا لاحقًا لا تعيد استخدام هوية دورة مركز سابقة.
- بعد إعادة تشغيل العملية، يُرفض التنفيذ حتى المصالحة الصريحة. بعدها يُستكمل الأمر الجزئي الموجود دون إعادة إرساله.
- إذا انخفض السعر دون حد أمر إغلاق سابق، يلغى المتبقي ثم يعاد تسعير الإغلاق بملاحظة جديدة. لا تسمح حجزات الخدمة ببيع كمية غير مملوكة أو محجوزة سلفًا.
- الإيقاف الطارئ يمنع الدخول ويبقي إغلاق العقود المملوكة ممكنًا داخل حساب `paper/mock` موثوق وأسعار صالحة. تغيير الحساب إلى `shadow/analysis` يمنع جميع عمليات التنفيذ الجديدة، بما فيها البيع.

## التشغيل

من مجلد `backend` وبعد إعداد الخادم وقاعدة البيانات وفق README:

```bash
python -m app.worker --once
python -m app.worker --execute-mock --interval 30
```

الأمر الأول تحليل فقط. الأمر الثاني ينفذ الأتمتة للحسابات المفعلة صراحة فقط. يمكن أيضًا استخدام واجهة الحساب:

```text
POST /api/accounts/{account_id}/automation/run
Authorization: Bearer <رمز الخادم المحلي>
Content-Type: application/json

{}
```

لا تقبل هذه الواجهة أسعارًا أو أوامر أو تعليمات نموذج لغوي. تعتمد على المحركات والمصدر التجريبي المثبت داخل الخادم. يرجع التنفيذ `actions` و`blocked_reasons` وعدد الأوامر والتنفيذات ومراكز الانتهاء، مع `source=synthetic_mock` و`live_enabled=false`.

## حدود مقصودة يجب معرفتها

- ملاحظة السوق تنتهي بعد **60 ثانية**. العامل لا يجدد الملاحظة من تلقاء نفسه ولا يعيد تشغيل تغذية سبق تعطيلها. يلزم تحديث Mock صريح من التطبيق أو واجهة `/mock-market-data`؛ بعد انتهاء الملاحظة تُمنع الإدخالات والإغلاقات المسعرة آليًا حتى التحديث. يظل انتهاء العقد إجراء تسوية دفترية تحفظيًا مشروطًا بثقة الحساب.
- بيانات الشموع والخيارات افتراضية. السعر الافتراضي للخيار 1.00/1.05 دولار ثابت لأغراض التوصيل؛ لا يمثل عرضًا حقيقيًا ولا يولد وقف خسارة أو جني ربح تلقائيًا بتغير سوق فعلي. تختبر تغيرات السعر بموفري اختبارات محليين، ويختبر زر التشغيل دورة تجريبية على هذه البيانات.
- لا يوجد اتصال خارجي أو تشغيل IBKR Paper، ولا ساعات جلسات سوق موثقة أو إغلاق عند نهاية الجلسة في هذا الإصدار. `intraday/swing` محفوظان كإعدادين؛ تطبيق سياسة زمنية مختلفة لكل منهما ما زال ناقصًا.
- محاكاة التنفيذ تستخدم السبريد الفعلي للبيانات المصطنعة. لا تضيف عمولة أو انزلاقًا إلى دفتر التنفيذ الآلي؛ محرك الاختبار التاريخي المنفصل يحتسب التكاليف والانزلاق والسبريد. لا تشكل أي نتيجة هنا دليل ربحية.
- خسارة اليوم والتعرض بالقيمة الدفترية يحافظان على سياسة V0.3. وقف الخسارة يعتمد على ملاحظة صالحة وقد يتأخر أثناء انقطاع البيانات؛ لا يضمن سعر خروج. تقييم شامل للأرباح غير المحققة وإدارة مخاطر سوقية أوسع ما زالا مطلوبين.
- المصادر المحقونة في `run_account(..., feed=..., quote_feed=...)` مخصصة للاختبارات المحلية، وتعمل تحت قفل المعاملة. لا تستعمل محولات شبكة فيها دون إعادة تصميم فصل جلب البيانات عن معاملة التنفيذ.
- لم تجر هذه المهمة اختبار تداول مالي أو تحققًا من جودة أسعار وسيط أو اعتماد إنتاج.
