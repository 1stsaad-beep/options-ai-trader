# تشغيل آمن ونسخ احتياطي وفحص أسرار — V1

هذا الدليل للمحاكاة المحلية فقط. لا يشتري استضافة، ولا يشغل وسيطًا، ولا يسمح بتفعيل Live. لا تحمل النسخة الاحتياطية أي ضمان لصحة رصيد وسيط أو حالة أوامره.

## نسخ SQLite واستعادته

الأداة `scripts/backup_restore.py` تستخدم واجهة SQLite online backup لنسخ حالة ملتزمة ومتسقة، بما فيها البيانات الموجودة في WAL. تفحص سلامة SQLite والعلاقات الخارجية، وتحسب SHA256 وحجم الملف، وتكتب manifest مجاورًا. صلاحية الملفين `0600`، والنشر ذري دون استبدال اسم موجود. ترفض الروابط الرمزية والملفات غير العادية ووجود ملف هدف أو WAL/SHM/journal/manifest للهدف. لا تمسح قاعدة أصلية أو حسابًا محفوظًا.

نفّذ من جذر هذا المشروع فقط، مع مسارات قاعدة المشروع المراد نسخها. اختر أسماء جديدة لكل محاولة:

```bash
umask 077
mkdir -p "$HOME/options-ai-trader-backups"
python scripts/backup_restore.py backup backend/options_demo.db "$HOME/options-ai-trader-backups/v1-before-upgrade.db"
python scripts/backup_restore.py verify "$HOME/options-ai-trader-backups/v1-before-upgrade.db"
python scripts/backup_restore.py restore "$HOME/options-ai-trader-backups/v1-before-upgrade.db" "$HOME/options-ai-trader-backups/v1-restore-review.db"
```

احفظ ملف `.manifest.json` مع قاعدة البيانات. الاستعادة تقرأ نسخة خاصة من الملف وتتحقق من البصمة ثم سلامة SQLite قبل نشر **ملف جديد فقط**. لا تعيد توجيه API أو worker تلقائيًا إلى النسخة المستعادة؛ أوقفهما، افحص النسخة المنعزلة، ثم بدّل الإعداد المحلي بنفسك إذا أردت. فتح قاعدة المشروع عبر Repository يلغي الثقة السابقة ويستدعي مصالحة Mock صريحة وفق سياسة الخدمة. لا تتجاوز ذلك باستعادة `state_known` يدويًا.

الـ manifest يكشف فسادًا أو تعديلًا غير متوافق، لكنه غير موقع. مهاجم يستطيع تبديل القاعدة والـ manifest معًا قد يمرر تغييرًا متسقًا. لا يوجد تشفير في هذه الأداة: استعمل تخزينًا محليًا مشفرًا بصلاحيات مناسبة، خارج Git، ولا ترسل النسخ أو كلمات المرور في المحادثة. حافظ على مساحة كافية لملف مؤقت إضافي. فحص `verify` ينشئ نسخة مؤقتة خاصة بجوار snapshot ولا يغير الأصل. المهلة الآمنة لنسخ قاعدة منشغلة 30 ثانية؛ فشل العملية لا يعطي إذنًا بحذف قاعدة أو تجاوز تحققها.

الملفان منفصلان وليسا معاملة نظام ملفات واحدة؛ انقطاع الطاقة بين نشر manifest ونشر القاعدة يمكن أن يترك manifest يتيمًا. إعادة المحاولة ترفض الاسم المستخدم. افحص الحالة واختر اسمًا جديدًا، ولا تعتبر وجود manifest وحده نجاحًا. أخطاء الأداة تُخرج نتيجة JSON عامة دون بيانات الصفوف أو محتويات الملفات.

## PostgreSQL

الأداة السابقة لا تدعم PostgreSQL ولا تتصل به. التخطيط التشغيلي هو `pg_dump` بصيغة custom من قاعدة المشروع، ثم استعادة إلى قاعدة **جديدة ومنعزلة** بواسطة `pg_restore --exit-on-error --single-transaction --no-owner --no-acl`؛ لا تستخدم `--clean` ضد قاعدة عاملة. اضبط الاتصال محليًا عبر ملف خدمة PostgreSQL وملف كلمات مرور بصلاحية `0600`، ولا تضع كلمة المرور في الأمر أو Git.

يمكن التحقق من توفر الأدوات دون اتصال:

```bash
pg_dump --version
pg_restore --version
```

خطوات التحقق المطلوبة لاحقًا: إنشاء اسم قاعدة استعادة جديد؛ التحقق من شهادة الخادم عند الاتصال البعيد؛ حفظ SHA256 خارج النسخة؛ فحص قيود المخطط، الحسابات، الأوامر، التعبئات، اللقطات وسجل الترحيلات؛ تشغيل مصالحة Mock على النسخة المنعزلة؛ توثيق مدة الاستعادة. يجب أن تُنقَل صلاحيات الأدوار والأسرار وإعدادات الخادم ضمن خطة مستقلة؛ ملف dump وحده لا يغطيها. لا توجد هنا نتيجة مزعومة لاختبار backup/restore PostgreSQL أو استعادة خادم حقيقي.

## فحص أنماط الأسرار

```bash
python scripts/security_scan.py --repository .
python scripts/security_scan.py --repository . --all-history
```

المخرجات JSON: المسار، مرجع Git، رقم السطر ونوع الاشتباه فقط. لا تُطبع القيمة المطابقة أو السطر أو بصمة السر. رمز الخروج `0` يعني عدم العثور على أنماط مطابقة ضمن النطاق، و`1` يعني نتائج تحتاج مراجعة، و`2` يعني فشل الفحص. لا يعني `0` أن المشروع خالٍ من الأسرار أو الثغرات.

النطاق الافتراضي ملفات Git المتتبعة بنسختها الحالية، ويشمل التغييرات المحلية في الملفات المتتبعة. الملفات الجديدة غير المضافة إلى Git والملفات ignored غير مفحوصة؛ أضف ملفات المصدر المطلوبة إلى الفهرس ثم أعد الفحص قبل commit. `--all-history` يفحص محتوى كل blob ومسار مميز يمكن الوصول إليهما من فروع ووسوم Git المحلية. لا يجلب فروعًا أو وسومًا بعيدة ولا يفحص كائنات Git غير القابلة للوصول. حزمة تاريخ Git المؤرشفة `.bundle` لا تُفتح تلقائيًا ويُعلن تجاوزها؛ فحص تاريخها يحتاج مستودعًا مستعادًا منفصلًا ومصرحًا به.

الأنماط تشمل مفاتيح خاصة، صيغًا معروفة لرموز GitHub/AWS/OpenAI/Slack وJWT، روابط قواعد بيانات تتضمن كلمة مرور، وتعيينات أسرار ذات تنوع حروف مرتفع. تُعلَّم أسماء ملفات التوقيع و`.env` والمفاتيح حتى لو لم يُفحص محتواها. الحد 8 MiB لكل ملف؛ الأرشيفات والثنائيات وغير UTF-8 تظهر في قائمة `skipped`. لا يوجد فك أرشيف أو تحقق من صلاحية الرمز لدى المزود، ولا فحص اعتماديات مدفوع.

استثناءات fixtures ضيقة ومعلنة: رموز الاختبارات القديمة ذات الأسماء الواضحة مستثناة **داخل مسارات الاختبارات فقط**، وكلمة مرور خدمة CI المؤقتة ومثال اتصال قاعدة محلية في `docs/DATABASE.md` ونسخته التاريخية مستثناة بقيمة SHA256 ومسار محددين داخل الشيفرة. تغيير القيمة يزيل الاستثناء. صيغ المفاتيح الحقيقية المعروفة لا تُستثنى لمجرد أنها داخل اختبار. استعمال fixture token خارج الاختبارات يولد نتيجة مراجعة. هذه الاستثناءات ليست أسرارًا إنتاجية ولا نمطًا صالحًا لمصادقة خادم منشور.

## HTTPS محلي اختياري

`infra/compose.https.yaml` و`infra/Caddyfile` يضيفان reverse proxy محليًا عند اختيار profile `local-https` فقط:

```bash
docker compose --env-file infra/.env -f infra/compose.yaml -f infra/compose.https.yaml --profile local-https config
docker compose --env-file infra/.env -f infra/compose.yaml -f infra/compose.https.yaml --profile local-https up --build -d
```

العنوان `https://localhost:8443` مربوط بـ`127.0.0.1` فقط. تبقى واجهة HTTP الأساسية على loopback كما في Compose الأصلي؛ قاعدة PostgreSQL غير منشورة للإنترنت. Caddy يستخدم CA داخلية، وواجهة إدارته معطلة، ولا يطلب شهادة عامة. مفتاح CA محفوظ في volume خاص خارج Git. لا تثبّت شهادة ثقة على الهاتف أو النظام دون مراجعة؛ ملف الإعداد لا يعطل التحقق من TLS في Flutter ولا يجعل شهادة محلية موثوقة تلقائيًا. أوامر Docker قد تنزّل الصور إذا لم تكن محلية؛ لم تُشغّل خلال اختبار السكربتات.

هذا مثال تطوير محلي غير معتمد للإنتاج. قبل أي نشر لاحق: تثبيت صورة Caddy ببصمة digest بعد فحصها، مصادقة مناسبة، DNS وشهادة موثوقة، سياسة جدار ناري وسرية/نسخ مفاتيح، تحديثات أمان ومراقبة. لا تفتح المنفذ لجميع العناوين لمجرد الوصول من الهاتف. الإعداد يتبع [توثيق Caddy الرسمي](https://caddyserver.com/docs/caddyfile/options) لخيار CA المحلية وإيقاف الإدارة وإعادة التوجيه.

## الاختبارات والحدود

`backend/tests/test_operations_v1.py` يغطي نسخ WAL، استبعاد كتابة غير ملتزمة، الاستعادة المنعزلة، منع الكتابة فوق الملفات وملفاتها الجانبية، سباق عمليتي نسخ، فساد البصمة وmanifest، قاعدة تالفة رغم بصمة متوافقة، الروابط الرمزية، فساد FK، تنقيح الأخطاء، صيغ الأسرار والاستثناءات، تاريخ Git، وحدود الفحص وإعداد HTTPS الثابت. يوجد أيضًا اختبار تكامل يستعيد دفتر Mock فعليًا لأربعة حسابات ويحافظ على أوامرها ومراكزها ومعرفاتها، ويثبت إلغاء الثقة عند إعادة الفتح ثم المصالحة دون إعادة إرسال. الاختبار الثابت لملفات HTTPS ليس تشغيل Caddy أو Docker أو اتصال TLS حقيقيًا. نتائج التشغيل الفعلية تُسجل في تقرير اختبار الإصدار.
