# Alpaca Basic — بيانات فقط، مرشح V1

مراجعة الوثائق: 2026-10-12. لا اتصال بحساب Alpaca في هذه الدفعة، ولا قراءة مفاتيح من التطبيق الآخر. لا إثبات لصلاحيات الحساب الفعلية حتى اختبار اتصال منفصل يوافق عليه المالك. لا تداول خارجي أو Paper أو IBKR أو Live، ولا اشتراك أو استضافة مدفوعة.

## ما تدعمه Basic وفق الوثائق الرسمية

| البيانات | المعلن | تطبيقنا وحدوده |
|---|---|---|
| أسهم/ETF | فورية من IEX فقط، وليست كل البورصات | `feed=iex` صريح؛ آخر صفقة وعرض OHLCV، مع توقيت وعمر |
| تاريخ الأسهم | منذ 2016؛ SIP الحديث مقيد، والتاريخ SIP يتطلب نهاية أقدم بـ15 دقيقة دون الاستحقاق الفوري | هذه النسخة تطلب IEX فقط؛ لا تحويل تلقائي إلى SIP |
| خيارات Basic | Indicative: عروض معدلة، وصفقات مشتقة متأخرة 15 دقيقة | يعرضها للتحليل والمراقبة؛ لا يصفها بأسعار OPRA فعلية |
| تاريخ الخيارات | يبدأ في فبراير 2024 وفق الوثائق | OHLCV بخاتمة لا تتجاوز الآن ناقص 15 دقيقة؛ رفض 403 واضح |
| OPRA فوري | ليس افتراضًا في Basic | غير مفعّل؛ لا شراء أو ترقية آلية |
| الحدود | 200 طلب تاريخي/دقيقة؛ بث الأسهم 30 رمزًا، الخيارات 200 عرض | REST فقط، ميزانية افتراضية 30 طلبًا/دقيقة، لا اتصال بث |

المصادر الرسمية: [الاشتراكات والمصادقة](https://docs.alpaca.markets/us/docs/about-market-data-api)، [IEX/SIP والتاريخ](https://docs.alpaca.markets/us/docs/market-data-faq)، [طبيعة بيانات الخيارات](https://docs.alpaca.markets/us/docs/historical-option-data)، [Latest quotes](https://docs.alpaca.markets/us/reference/stocklatestquotes-1)، [Latest trades](https://docs.alpaca.markets/us/reference/stocklatesttrades-1)، [Stock bars](https://docs.alpaca.markets/us/reference/stockbars)، [Option bars](https://docs.alpaca.markets/us/reference/optionbars)، [Option chain](https://docs.alpaca.markets/us/reference/optionchain).

الاشتراك لا يُعامل هنا كتصريح لإعادة نشر أو بيع البيانات. تعرض كل نتيجة أن الاستخدام خاضع لاتفاقيات Alpaca والبورصات؛ التطبيق لا يمنح حق إعادة توزيع. راجع [الإفصاحات والاتفاقيات الرسمية](https://alpaca.markets/disclosures) الخاصة بحسابك قبل أي مشاركة أو استخدام تجاري. حقوق العرض الفعلية للحساب لم تُتحقق بجلسة مصادقة.

## المسار المعزول

- `backend/app/market_data.py`: واجهة `MarketDataProvider` لا تحتوي عمليات حساب/تداول. يمكن استبدالها بمزود لاحق دون تغيير دفتر التنفيذ.
- الناقل يسمح فقط بـGET إلى `https://data.alpaca.markets:443` ومسارات أسعار محددة. لا عنوان قابل للتخصيص، ولا SDK تداول، ولا redirect أو وكيل بيئة تلقائي. جسم الاستجابة محدود 4 MiB؛ أخطاء المزود الخام لا تصل للمستخدم.
- `OAT_ALPACA_DATA_APPROVAL` غير مضبوط افتراضيًا؛ الخدمة تعرض `DISABLED_PENDING_SEPARATE_APPROVAL`. إنشاء الكائن/قراءة حالته لا يفتح اتصالًا.
- مفاتيح هذا المشروع لها أسماء خاصة به ولا تُكتشف من متغيرات `APCA_*` أو ملفات مشروع آخر. لا نفترض أن مفتاح الحساب نفسه محدود بصلاحية أسعار فقط؛ المنع في مسار التطبيق والناقل. يجب إبقاء الاعتماد في الخادم وحمايته بصلاحيات نظام التشغيل.
- 128 عنصر cache، TTL ثلاثون ثانية للقطات وخمس دقائق للتاريخ؛ تاريخ التقاط البيانات محفوظ، فلا تتحول نسخة cache إلى سعر جديد. لا fallback إلى سعر قديم عند فشل طلب منتهية صلاحيته، ولا إلى بيانات اصطناعية.
- قفل مشترك يدمج طلبات الرمز نفسه المتزامنة بين الحسابات داخل العملية. لا اشتراكات WebSocket أو إعادة اتصال بث؛ إعادة المحاولة تخص REST، بحد محاولتين للأخطاء العابرة. 429 يوقف الطلبات حتى التهدئة؛ 401/403 يقفل المزود حتى مراجعة الإعداد وإعادة الخدمة.
- الميزانية الافتراضية 30 طلبًا/دقيقة ومقاييس الطلبات/cache/retries وحدود المزود متاحة عبر API. هذه ليست حصة مضمونة: التطبيق الآخر قد يستهلك الرصيد نفسه. استخدم عامل API واحدًا لهذه النسخة؛ تنسيق الميزانية بين عمليات أو تطبيقات مستقلة غير منفذ. لا نقرأ أو نغير إعدادات التطبيق الآخر ولا نفتح اتصال بث قد ينافسه.
- الصفحات محدودة افتراضيًا بخمس، وتظهر `complete=false` عند نفادها. تقطع الطلبات غير الصالحة والمتكررة الدورانية. تاريخ الأسهم خام مع `asof=-` لتجنب إعادة تسمية تاريخية تلقائية.

## الحسابات وReal Market Data + Virtual Trading

المسار الجديد هو `/api/accounts/{id}/market-data/…`، يتطلب Bearer الخاص بالخادم والحساب والرمز الموجود في قائمة ذلك الحساب. الرموز التي يضيفها المستخدم مدعومة حتى لو كان حقل `enabled` الاصطناعي معطلًا. وصول بيانات حقيقية لا يعدل `verified`، ولا يغير حدود المخاطر أو أذونات الاستراتيجيات.

| المسار بعد `/market-data` | السلوك |
|---|---|
| `GET /status` | الاتصال والميزانية والرموز وحالة `ANALYSIS_ONLY` |
| `GET /stocks/{symbol}/snapshot` | صفقة IEX وعرضها؛ السعر مفقود يبقى null |
| `GET /stocks/{symbol}/bars?start=…&end=…&timeframe=…` | OHLCV مكتمل، الفواصل 1Min/5Min/15Min/1Hour/1Day |
| `GET /options/{symbol}/chain` | عقود إرشادية؛ Greeks من المزود فقط أو null |
| `GET /options/{symbol}/bars?contract=…&start=…&end=…&timeframe=…` | تاريخ العقد؛ لا تأهيل عقد أو تعبئة |
| `POST /virtual-orders` | رفض 409 موثق بسبب `INDICATIVE_OPTIONS_NOT_EXECUTABLE`؛ لا أمر مقبول أو تعبئة |

الوضع `real_market_virtual` مستقل عن Demo Synthetic. **في Basic الحالي هو تحليل ومراقبة فقط، وليس تنفيذ خيارات وهميًا بأسعار حقيقية مكتملًا.** لا تذهب المشاهدات إلى `option_marks` أو `market_snapshots` الاصطناعية ولا إلى submit/fill الحاليين. مصدر بديل مؤهل يحتاج قبولًا منفصلًا وتكاملًا محليًا مختبرًا: عرض خيار فعلي حديث، أحجام وسبريد وعقد مؤهل، مخاطر انتهاء وتسوية، وفحص المخاطر عند القبول والتعبئة. لا يكفي تغيير اسم feed إلى OPRA لفتح التنفيذ، ولا يوجد خيار API لتجاوز القفل.

واجهة الهاتف ضمن لوحة الخادم ← «بيانات السوق الحقيقية». إدخال Alpaca keys غير موجود. الطلبات يدويّة، والحسابات هنا حسابات الخادم؛ مخزن Demo المحلي مستقل ولا يُرحّل تلقائيًا. تعرض الواجهة مصدر السعر وتوقيته وحدود التأخير، وشموعًا خامًا قابلة للتكبير والتحريك وآخر 120 شمعة مستلمة. تعرض أول 20 عقدًا مستلمًا مع العدد الفعلي وتحذير الصفحات الجزئية. المختبرات البحثية وقرارات Demo القديمة باقية؛ **لم تُربط محركات Elliott أو التداول الآلي بهذه البيانات الجديدة**.

## اتصال آمن — لا يُنفذ إلا بعد موافقة منفصلة

1. أبقِ التطبيق الآخر يعمل كما هو. لا تدوّر مفتاحه أو تعيد توليده ولا تنسخ ملف إعداداته. راجع بنفسك صلاحيات Basic واستخدام الحساب وحدود البيانات.
2. على خادم Options AI Trader فقط، جهّز القيم عبر مخزن أسرار أو بيئة خدمة خاصة، خارج Git/APK والـlogs: `OAT_ALPACA_DATA_KEY_ID` و`OAT_ALPACA_DATA_SECRET_KEY`. لا ترسلها في المحادثة ولا تضعها في معاملات الأوامر أو `--dart-define`. لا تُطبع نتيجة `docker compose config` المحلولة لأنها قد تكشف البيئة.
3. بعد الموافقة على القراءة فقط، يضبط المشغّل `OAT_ALPACA_DATA_APPROVAL=read_only_approved` وميزانية صغيرة مثل 10 أو 30 في `OAT_ALPACA_DATA_REQUESTS_PER_MINUTE`. القيمة الافتراضية دون هذا الإقرار تعطل الاتصال. لا endpoint يستطيع تفعيلها.
4. شغّل API بعملية واحدة، مستخدم خدمة محدود، HTTPS أو نفق محلي ومصادقة الخادم الحالية. داخل Docker أضف صراحة `-f infra/compose.alpaca-data.yaml` بعد ملف Compose الأساسي؛ الملحق يمرر مفاتيح API فقط، ولا يمررها إلى worker. لا يتم تفعيله ضمن CI أو التشغيل الافتراضي.
5. افحص `/market-data/status` أولًا (بلا طلب إلى Alpaca). وافق على اختبار رمز واحد من قائمة الحساب، ثم GET snapshot وOHLCV تاريخي محدود وسلسلة إرشادية. راقب 429 وprovider_remaining وعمر البيانات، وتأكد أن التطبيق الآخر لم يتأثر. لا ترسل أي أمر Paper/Live أو IBKR.
6. التحقق من keys/entitlements الحقيقية واللاتنسي وإعادة الاتصال تحت انقطاع فعلي يبقى اختبار قبول منفصلًا. للإيقاف، أزل إقرار الاتصال من إعداد هذه الخدمة وأعد تشغيل API؛ لا تغير مفاتيح التطبيق الآخر.

## الاختبارات وحدود البحث

55 اختبار موصل أولي و15 اختبار API/عقد مشترك لاحق، جميعها باستخدام ردود Mock دون حساب حقيقي. الـfixture التاريخي يوثق مثال AAPL/IEX بتاريخ 2023-09-29 من FAQ الرسمية، لا جلبًا حيًا للحساب. Python وFlutter يقرآن عقد نتائج مشتركًا مولدًا من الموصل؛ الواجهة ترفض هوية الحساب أو المصدر أو الصلاحيات المخالفة.

يرفض تاريخ الشموع المستقبل وتداخل الترتيب ويستبعد الشمعة غير المكتملة عند cutoff. إكمال اليوم يستخدم منتصف الليل التالي في New York (محافظ، يشمل DST). لكن تاريخ المزود المسترجع اليوم قد يحتوي تصحيحات لاحقة؛ لا يمثل أرشيف point-in-time. لذلك `point_in_time_backtest_verified=false` دائمًا. لا Backtest خيارات خارج العينة أو إثبات ربحية ولا Greeks محلية مخترعة.

النتائج النهائية وروابط CI وAPK والبصمات تُثبت في تقرير التسليم لهذه الدفعة بعد اكتمال بوابات القبول. حالة الهاتف الفعلي والاتصال الحقيقي تبقى «لم يُنفذ» حتى دليل منفصل.
