## ما أثبته المختبر الفعلي

- PostgreSQL وAPI والعامل والبوابة وصلت إلى الحالة healthy. قاعدة البيانات لا تنشر منفذًا، ولا ينشر API أو العامل منافذ؛ البوابة وحدها تعلن127.0.0.1:18019.
- API والعامل وPostgreSQL على الشبكة الداخلية فقط. البوابة على شبكتي الدخول والداخلية، وتوجه إلى API ثابت. API والعامل والبوابة غير جذرية وبنظام ملفات للقراءة فقط. ظل المزود معطلًا والتنفيذ مقفلًا.
- رفض غياب الرمز وخطئه بـ401؛ نجحت قراءة حسابي Phone Lab وحالة محرك حديثة وأحداث كل حساب. الأوامر والمراكز فارغة في الحسابين.
- تغيير إعداد A لم يغيّر B؛ عاد الإعداد الأصلي بعد تجربة الأداة. رفض الإقرار بحدث A عبر حساب B، ونجح الإقرار من الحساب الصحيح. رُفضت كتابة المخاطر غير المسموحة.
- إيقاف المختبر احتفظ بالحجوم والملفات الخاصة؛ لا تحذف الأداة أي قاعدة بيانات أو ملف. أما اختبارات المشروع الأساسية السابقة فلها fixtures مؤقتة مستقلة، ولم تصل إلى بيانات مستخدم.

الحالة `DISABLED` متوقعة مع تعطيل مصدر السوق؛ وجود نبض حديث يثبت حياة العامل فقط. لا توليد لأسعار سوق أو ادعاء تحليل سوق حقيقي، ولا اتصال Alpaca/IBKR أو أوامر خارجية أو Live أو شراء. أحداث هذا الاختبار وإعداداته لا تمثل بيانات Demo القديمة.

## الإصلاحات والمحاولات المحفوظة

الدفعة الأولى أنشأت المختبر والأداة الخاصة بالرمز. اختبار Docker كشف أن الشبكة الداخلية وحدها لم تعلن منفذ API؛ أضيفت بوابة منفصلة مع إبقاء الخدمات الأساسية معزولة. فشل بدء البوابة التالية؛ فحص صورة Caddy الرسمية كشف صلاحية ملف تنفيذي تتعارض مع إسقاط كل صلاحيات الحاوية. أزيلت الصلاحية عند بناء صورة ثابتة2.11.7 بدل منح صلاحيات إضافية، ثم نجح المختبر كاملًا. لا نختزل الفشل الأول في مشكلة هاتف أو رمز خاطئ.
