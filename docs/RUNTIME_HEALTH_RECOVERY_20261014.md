# Runtime probe and shutdown recovery — batch17

A process regression reproduced both workers creating a missing database when invoked only with `--healthcheck` (2 failing checks before the fix). The old path constructed Repository, ran migrations and acquired the financial writer/advisory lock. Thus previous account-preservation tests did not prove a truly read-only probe.

`backend/app/runtime_health.py` now uses SQLite URI mode=ro plus query_only, or a PostgreSQL connection with default_transaction_read_only, bounded connect/query/lock timeouts. The probe selects one named heartbeat without migrations, provider construction, account updates or application locks. Missing databases, unknown/malformed/stopped/future/stale payloads fail closed using exit status only; database paths and exceptions are not printed. Healthy DISABLED/BACKOFF/indicative states describe collector liveness, never market or execution readiness.

Both worker CLI health paths use this reader before creating Repository or registering signal handlers. Collector graceful SIGTERM/SIGINT writes STOPPED atomically with releasing its lease; only the current owner can do so, so a delayed old process cannot stop a successor. API heartbeat freshness uses the same payload/state validation. Follow-up: completed `--once` invocations also record STOPPED. Tick receipts remain intact, but a completed maintenance process no longer leaves daemon liveness healthy.

Targeted local verification: **56 passed**, one pre-existing FastAPI/Starlette TestClient deprecation warning. The selected modules cover probes, synthetic worker recovery, collector entrypoint/runtime and monitoring. New process acceptance includes a missing database, minimal unmigrated schema with byte-preservation, a concurrent SQLite writer, malformed/future/stale/stopped state, graceful shutdown preserving the account/zero orders, stale-owner fencing, and actual database-outage recovery without network or phone. PostgreSQL acceptance harness adds a read-only write-denial check while another connection holds the application advisory lock, and immediate shutdown invalidation; those extra two checks await CI on this commit.

This is a concrete runtime correctness improvement. It does **not** implement a durable OPRA-priced Market Paper execution worker, prove phone-off trade protection, deploy Oracle, or establish long-duration soak or independent review. No provider credentials, live/external orders or APK were used.
