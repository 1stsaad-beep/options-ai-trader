# Batch49 — independent observed-worker watchdog

`python -m app.observed_paper_watchdog` is a separate opt-in process. It never constructs Repository, migrates a schema, creates an absent database, reads provider credentials, takes a worker lease, reconfigures an account or sends a financial order. With `OAT_OBSERVED_MONITOR_APPROVAL=monitor_only_approved`, it samples the existing database every15 seconds. `--once` performs one sample; `--healthcheck` is a bounded read-only probe. Default startup is disabled, including when inherited provider variables happen to exist.

The monitor serializes a fresh status read and deduplicated inbox append in one short transaction using the worker's existing advisory/writer lock. A heartbeat older than60 seconds or in the future is unavailable. The detection time is recorded without claiming a failure start time. The existing owner inbox immediately carries the outage while the worker remains dead. On actual worker recovery, its normal heartbeat transaction resolves the condition; the monitor never restarts, enables or silently reconciles trading. Provider auth/backoff, worker lease, balances, receipts and originals remain untouched.

A separate observed_watchdog health row records its last successful sample. Graceful shutdown marks only its own row STOPPED; an old instance cannot invalidate a newer instance. SQLite opens with mode=rw and a1-second lock bound; PostgreSQL uses3-second connect,2-second statement and1-second lock timeouts. Failed alert writes roll back the health update. No schema change is required.

Database failure or journal corruption prints only MONITOR_UNAVAILABLE. It cannot persist an alert in an unavailable database; an operator's independent log/health collection is still needed for host/database outages. No external push destination, credential or remote message has been configured. These are operational integration limits, not successful delivery claims.

The existing opt-in Compose override includes a separate observed-watchdog service without provider secrets. Its separate `observed-watchdog` profile must be explicitly selected alongside the approval variable; the ordinary `observed-paper` profile does not start it. Nothing has been deployed or enabled. Existing CI exercises PostgreSQL connections and original-ledger preservation. Tests use two concurrent monitors, a stopped worker, recovery, clock regression, absent/legacy databases, write rollback, successor shutdown and actual isolated subprocesses without provider keys.
