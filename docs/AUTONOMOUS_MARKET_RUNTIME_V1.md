# تسليم مرحلي: خدمة بيانات وتحليل مستقلة عن الهاتف

التاريخ: **2026-10-12**. الفرع: `recovery/v1.0-20261011`.
مصدر بوابة القبول: `a4b7dca6956ada7a73edefef2ce5817bd745f2f6`؛ راجع إيصال الأدلة المرفق لأحدث نتائج CI ورأس التقارير اللاحق.

**هذا ليس إعلان تشغيل تداول خيارات 24/7.** أصبح هناك عامل Backend مستقل لجمع بيانات السوق وتحليلها وحفظها ومراقبتها. لم يُنشر على خادم شخصي دائم، ولم يتصل بحساب Alpaca. تنفيذ الخيارات بأسعار السوق ما زال مقفلاً: أسعار Basic الإرشادية ليست عروض OPRA فعلية مؤهلة للتعبئة. محرك Demo Synthetic السابق مستقل ومحفوظ، ولا تُنقل أسعاره أو أمواله إلى الوضع الجديد.

## حدود Basic والموارد المشتركة

وثائق Alpaca الرسمية التي روجعت في 2026-10-12 تصف Basic بأنه مجاني، لحظية الأسهم من IEX فقط، وخيارات indicative لا OPRA الفورية. حد طلبات التاريخ المعلن200/دقيقة، وحد اشتراكات الأسهم30 رمزًا والخيارات200 quote. كثير من خطط streaming تسمح باتصال واحد لكل endpoint؛ لذلك هذا العامل يستخدم REST فقط. الأسعار الإرشادية مشتقة ومعدّلة وليست عروض OPRA الحقيقية؛ تداولاتها متأخرة15 دقيقة. تاريخ الخيارات المتاح يبدأ فبراير2024. الصلاحيات الدقيقة للحساب لم تُختبر ولا تمنح هذه الإضافة حقوق إعادة توزيع.

المصادر: [خطط Market Data](https://docs.alpaca.markets/us/docs/about-market-data-api)، [Streaming وحد الاتصال](https://docs.alpaca.markets/us/docs/streaming-market-data)، [بيانات الخيارات](https://docs.alpaca.markets/us/docs/historical-option-data)، [الإفصاحات وحقوق الاستخدام](https://alpaca.markets/disclosures).

الميزانية المحفوظة تُنسق نسخ **هذا العامل** فقط. لا تعرف طلبات التطبيق الآخر ولا تضمن عدم استهلاكه الحصة كلها. عند429 يوقف العامل الطلبات ويحفظ مهلة المزود عبر إعادة التشغيل. عند401/403 يقفل الاتصال حتى صيانة مصرح بها. لا يجوز تدوير مفاتيح الحساب المشترك أو إعادة توليدها دون تقييم أثر ذلك على التطبيق الآخر. لا يُستخدم ملفه أو مفتاحه المخزن تلقائيًا.

حد التشغيل الحالي30 رمزًا مميزًا بين الحسابات، وطلبان أقصى لتصفح صفحات العقد في إعداد العامل. النتيجة الجزئية تُوسم ولا تتحول إلى تحليل صالح. جلب snapshot كل60 ثانية، والشموع وسلسلة الخيارات كل300 ثانية عند توافر الميزانية؛ ليست هذه خدمة أسعار tick-by-tick أو ضمان حداثة لكل رمز. يظل أكثر من30 رمزًا حالة `DEMAND_LIMIT_REACHED` تحتاج خفض الطلب أو تصميم توسعة مقبول.

**قيد سعة مهم:** الأرشيف الحالي1000 مشاهدة/حساب أو64MiB، و2MiB للمشاهدة؛ يتوقف التجميع لذلك الحساب عند الامتلاء، دون حذف أو تدوير التاريخ. رمز واحد قد يولد قرابة546 مشاهدة في جلسة6.5 ساعة، وثلاثة رموز قرابة1638 قبل أثر الميزانية/الفشل. لذلك لا يصلح الحد الحالي لإقامة غير محدودة؛ تطوير تصدير/أرشفة موثقة وسياسة سعة دون فقدان دليل شرط قبل تشغيل دائم. لا يكفي تكبير القرص وحده. الحالة `collection_block_reason` وصندوق الأحداث يوضحان الامتلاء.

## عقد التشغيل والمراقبة

- عملية واحدة تمتلك lease لمدة120 ثانية؛ العامل الآخر standby، وتتحقق الملكية مجددًا قبل نشر المشاهدة أو التحليل. لا تمسك معاملة DB أثناء HTTP. إعادة التشغيل تحفظ budget/backoff وأصل المشاهدات. lease ليس وعدًا بمنع كل طلب HTTP مكرر في حال تعليق نظام التشغيل؛ هو يمنع العامل القديم من نشر نتائج بعد انتقال الملكية. لا توجد أوامر مالية أصلًا.
- النبض كل5 ثوانٍ تقريبًا؛ بعد30 ثانية تظهر `WORKER_UNAVAILABLE`. عمليات HTTP طويلة أو أعطال التخزين قد تجعل النبض قديمًا، وهذا تعطل ظاهر لا ترخيص تنفيذ. Docker healthcheck يثبت نبض العملية فقط؛ لا يثبت اتصال Alpaca أو صلاحية الأسعار أو ربحية الاستراتيجيات. يلزم مراقب خارجي للكشف عن موت الخادم بالكامل.
- أسعار `latest` تُعاد مقارنة توقيتها بوقت الخادم. علم fresh في replay هو كما سُجل، وليس صلاحية حالية. الشموع تدخل التحليل بتوقيت **إغلاق الفترة**، مع فحص المستقبل والتقادم والفجوات. ربط الإشارة بالمشاهدة المسجلة لا يثبت توافر التاريخ بأثر رجعي.
- تحليل bars ينتج اقتراحات فقط؛ لا تُصنع Greeks/أسعار مفقودة. خيارات Basic تبقى `INDICATIVE_OPTIONS_NOT_EXECUTABLE` ولو وُجدت إشارة CALL/PUT.
- إعدادات الحساب تتطلب `expected_version`؛ يرفض التعديل المتزامن المتعارض. تعطيل الحساب أثناء fetch يمنع حفظ قرار لاحق بالإعداد القديم. الحصة الواحدة للرمز تُوزع على إيصالات منفصلة للحسابات.
- التطبيق الحالي نموذج operator واحد بتوكن واحد يملك جميع الحسابات، وليس نظام تعدد مستخدمين مستقل الصلاحيات. العزل هنا عزل الحسابات والدفاتر، لا صلاحيات عملاء مختلفين. افصل صلاحيات مستخدمي الهاتف قبل خدمة متعددة المستخدمين.

## تشغيل آمن بلا اتصال فعلي

هذه خطوات تجهيز للمشغل، لم تُنفذ على خادم خارجي في هذه المهمة:

1. خادم Linux مستمر، Docker Engine وCompose، مزامنة وقت، قرص دائم لقاعدة البيانات، ونسخة احتياطية منفصلة عن الخادم. توصية هندسية أولية:2vCPU/4GiB RAM و40–80GB SSD؛ ليست نتيجة load test. PostgreSQL16 في Compose، والمنافذ الحالية localhost فقط.
2. انسخ checkout للـcommit المقبول. خذ backup موثّق قبل migration7؛ لا تشغّل binary أقدم على schema7، ولا تستخدم reset أو حذف volume. أوقف الجامع عند استعادة نسخة؛ أدوات المشروع تستعيد إلى قاعدة جديدة ولا تستبدل القديمة.
3. أنشئ خارج المستودع دليلًا خاصًا، مثل `/srv/oat-secrets`، بملف إعدادات runtime مقيد القراءة يحمل كلمات PostgreSQL وتوكن API العشوائي، و`OAT_ALPACA_SECRET_FILE` كمسار فقط. لا تعرض الملفات أو ناتج `docker compose config` في محادثة/سجل عام. قاعدة البيانات وتوكن API لا تزالان في بيئة الحاويات الخاصة بهما؛ هذا لا يحوّلها إلى مدير أسرار كامل.
4. ابدأ بملف Alpaca فارغ `{}` خارج المستودع، و`OAT_ALPACA_DATA_APPROVAL` غير مضبوط، وباقي القيم `TRADING_MODE=paper`, `BROKER_PROVIDER=mock`, `ENABLE_LIVE=false`. العامل لا يقرأ الملف ما لم يحصل على sentinel الموافقة. Docker secrets هنا bind-file محلي لا تشفيرًا مُدارًا؛ يلزم تشفير القرص/النسخ بحسب الخادم.
5. من مجلد المشروع، بعد تجهيز ملف الإعدادات الخاص:

```bash
env -u OAT_ALPACA_DATA_APPROVAL docker compose \
  --env-file /srv/oat-secrets/runtime.env \
  -f infra/compose.yaml -f infra/compose.market-runtime.yaml \
  --profile market-runtime up -d --build
```

ملف `runtime.env` في هذه المرحلة لا يحتوي موافقة Alpaca. لا تجمع هذا الملف مع `infra/compose.alpaca-data.yaml`؛ ذاك مسار يدوي سابق. وضع `api_cache_only` يعطل إنشاء موصل API ويجعل المفاتيح في العامل وحده. Synthetic worker يعمل مستقلاً، ووجوده لا يعلن تشغيل تداول السوق.

6. تحقق من heartbeat ونسخة DB واستمرار العامل بعد إغلاق API/الهاتف. قبل أي وصول عبر الإنترنت جهّز HTTPS موثوقًا وجدارًا ناريًا وauth مناسبًا؛ overlay HTTPS السابق خاص بالتجربة المحلية ولا يثبت نشرًا عامًا آمنًا. لا تفتح PostgreSQL للعامة.

## ربط Alpaca بعد موافقة منفصلة فقط

يُراجع أولًا: مصدر الخادم، TLS وDNS ومزامنة الوقت، عدم وجود SDK/مسارات أوامر، قواعد خروج الشبكة، حصة REST المشتركة، عزل الأسرار، backup، حدود الأرشيف، وآلية مراقبة التعطل. النقل الحالي محدد إلى GET عبر HTTPS على `data.alpaca.markets` ومسارات البيانات المحددة؛ طبقة الشبكة المضيفة ليست بعد egress firewall تم اختباره.

يُدخل المشغل بنفسه زوج Alpaca عبر مدير أسرار أو ملف خاص **على الخادم**: حقلان فقط `key_id` و`secret_key`. لا تُرسَل القيم بالمحادثة، ولا توضع في APK/Git أو command arguments. الملف regular وليس symlink، لا يسمح بقراءة المستخدمين الآخرين، ويحجم إلى4096 bytes. اجعله0400 مملوكًا UID10001، أو0440 ومجموعة تسمح لمستخدم الحاوية UID/GID10001 بالقراءة. لا تستبدل أو تدوّر مفاتيح التطبيق الآخر. منح الكود وصول بيانات فقط لا يعني أن المفتاح نفسه محدود الصلاحيات لدى المزود؛ هذا حد مهم.

بعد الموافقة الصريحة وحدها، يضبط المشغل sentinel `OAT_ALPACA_DATA_APPROVAL=read_only_approved` في إعدادات خدمة الجامع، ويعيد إنشاء هذه الخدمة ثم يفعل **حساب اختبار واحدًا ورمزًا واحدًا** للمراقبة فقط. يسجل المصدر والتأخير و429 والذاكرة ومقارنة timestamps. لا تفتح خيارات حتى بتوكن صالح؛ gate التنفيذ ثابتfalse.

قفل401/403 محفوظ. بعد إيقاف الجامع وتصحيح الصلاحيات/الملف بموافقة، يمكن للمشغل تشغيل `python -m app.market_runtime_worker --reset-auth-lock` على نفس قاعدة البيانات كصيانة خاصة؛ يسجل حدثًا ولا يتصل بالمزود. لا يستخدم ذلك لتجاوز رفض الصلاحيات.

## النسخ والاستعادة

إعادة استخدام `scripts/postgres_backup_restore.py` و[دليل قاعدة البيانات](DATABASE.md). يمر اتصال PostgreSQL من متغير بيئة خاص، وبيانات المصادقة عبر ملف مؤقت مقيد، لا command arguments. يجب توفر pg_dump/pg_restore الإصدار16.

```bash
python scripts/postgres_backup_restore.py backup /secure-backups/runtime-20261012.dump
python scripts/postgres_backup_restore.py verify /secure-backups/runtime-20261012.dump
python scripts/postgres_backup_restore.py restore /secure-backups/runtime-20261012.dump \
  oat_restore_acceptance --trusted-project-archive
```

تستخدم الأدوات `OAT_POSTGRES_URL` الخاص افتراضيًا. لا تكتب قيمة الاتصال في الملف المتتبع أو المحادثة. checksum يكشف تغير الأرشيف ولا يشفر محتواه. شغّل الاستعادة على هدف جديد واختبر الأحداث الأصلية وتوكنات الوصول وصلاحيات DB، وأبقِ الجامع معطلًا حتى مراجعة ساعة الخادم وحالة retry؛ النسخة القديمة لا تعرف طلبات تمت بعد أخذها. الجدولة اليومية، تشفير النسخ، نقلها خارج الخادم، واختبار استعادة دوري على خادم حقيقي ما زالت إعدادات تشغيل مطلوبة، لا خدمات منشورة.

## خطة ربط Flutter

1. شاشة مستقلة باسم «خادم السوق — مراقبة فقط»؛ لا تستخدم `DemoStore` أو حساباته المالية المحلية كدفتر السوق. يعرض الهاتف رابط الخادم الموثوق وتوكن جلسة مخزنًا بطريقة نظامية، ولا يستقبل مفاتيح Alpaca.
2. اقرأ `GET /api/accounts/{account_id}/market-runtime/status`: النبض، حالة العامل، حداثة كل رمز، قفل التنفيذ، وامتلاء الأرشيف. لا تحول healthcheck إلى شارة «التداول يعمل».
3. إعداد التجميع لكل حساب عبر `PUT .../config` بجسم `{"expected_version":0,"enabled":true,"strategies":{"breakout":true,"pullback":false}}`. حدود Demo لا تتغير؛ زر التحكم يفعّل التحليل فقط، ولا يمنح موافقة الاتصال الخارجية.
4. اقرأ `GET .../events?limit=50` واعرض سبب القرار/التعطل و`observation_id`/digest. الإقرار عبر `POST .../events/{event_id}/ack`، والتفاصيل الأصلية عبر `GET /api/accounts/{account_id}/market-data/observations/{observation_id}`. صندوق الأحداث حاليًا آخر100 كحد أقصى؛ paging/Push ووضع offline جديد لم تنفذ بعد.
5. قبل إنشاء APK جديد: Widget/RTL/error/offline tests، فصل endpoints وDemo data، اختبار تدوير توكن API وإعادة الاتصال دون أوامر، ثم هاتف فعلي. لا تعِد بناء Lab17 لمجرد تغير الخادم. في هذا topology قراءات Lab17 اليدوية للمزود ستظل معطلة؛ لم تُربط بعد بواجهات cache الجديدة.

## التكاليف المتوقعة — ليست مشتريات

مثال عام مُراجع من [DigitalOcean Droplets](https://www.digitalocean.com/pricing/droplets): Regular Basic ‏1vCPU/2GiB بسعر12USD شهريًا، أو2vCPU/4GiB بسعر24USD. [النسخ الأساسية](https://docs.digitalocean.com/products/backups/details/pricing/) تضيف20% أسبوعيًا أو30% يوميًا؛ يصبح مثال4GiB نحو28.80–31.20USD شهريًا قبل الضرائب والدومين والتخزين/النقل الإضافي. هذه أسعار مثال منشورة، وليست إثبات أداء أو موافقة شراء. PostgreSQL داخل نفس الخادم لا يحتاج خدمة managed منفصلة؛ يزيد فقد الخادم الواحد أثر العطل. استضافة جهاز قائم قد لا تضيف فاتورة VM لكن تحتاج كهرباء وإنترنت وحماية ونسخًا مستقلة.

Alpaca Basic نفسه مجاني وفق الوثائق؛ لا اشتراك OPRA مدفوع اشتريناه أو افترضناه. لا تكلفة LLM مطلوبة لمسار التحليل الكمي الحالي. الإشعارات وخدمة مراقبة خارجية وتخزين نسخ خارجي قد تضيف تكاليف لاحقًا بعد اختيارها والموافقة.

- الأولوية التالية: معالجة سعة الأرشيف والتصدير غير الفاقد، ثم ربط شاشة الهاتف وصندوق التنبيهات، ثم تجهيز خادم آمن بمراقب خارجي وتجربة انقطاع واستعادة مستمرة. الاتصال بالبيانات يحتاج موافقة مستقلة؛ اختبار عمل24/7 يحتاج خادمًا مستمرًا فعلًا.
- تنفيذ الخيارات يحتاج مصدر عروض فعلية مؤهلة وبيانات عقد مكتملة واختبارات دفتر مستقل ومخاطر ورسوم/انزلاق وإغلاق/عكس. لا تصل البحث/الإشارات مباشرة بتنفيذ Demo. خروج السعر الغائب يظل غير منفذ، والعودة تتطلب عرضًا صالحًا دون تعبئات بأثر رجعي.
- احتفظ بتاريخ الفرع والأدلة. لا reset/force/clean أو حذف أرشيف/volume/فروع. إن ظهرت تغييرات غير محفوظة في جلسة تالية، احفظها قبل التطوير. لا تدّعِ استعادة ذاكرة عملية أو تغييرات جلسة غير محفوظة.
