# Options AI Trader — التثبيت والاختبار V1.0 RC1

## تثبيت Android وتجربة وضع الطيران

1. نزّل APK المرفق لهذا الإصدار، وتحقق من بصمته باستخدام `SHA256SUMS.txt`. استخدم الملف الموصوف **Preview** القابل للتثبيت؛ ملف `unsigned` ليس للتثبيت المباشر.
2. افتح APK من مدير الملفات. عند طلب Android، اسمح لهذا التطبيق بتثبيت الملف الذي اخترته. هذه نسخة تطوير للمحاكاة فقط.
3. معاينة V1 تستخدم `com.optionsaitrader.options_ai_trader.v1preview` وإصدار `1.0.0` ورقم بناء `10`، فلا تستبدل تثبيت V0.5. احتفظ بالتطبيق السابق وبياناته؛ لا تحذفه لحل اختلاف شهادة.
4. افتح التطبيق في **Demo محلي** وفعّل وضع الطيران. البيانات والأسعار والأموال اصطناعية، ولا تدخل بيانات وسيط أو كلمة مرور.
5. تظهر أربعة حسابات تجريبية عند أول تشغيل. أضف حسابًا خامسًا لتجربة عدم وجود حد ثابت، وغيّر قائمة مراقبته ومخاطره؛ راقب استقلال الحسابات الأخرى.
6. من الاستراتيجيات فعّل أتمتة الحساب المختار، ثم تقدم خطوة سوق محلية للقرار وأخرى للتعبئة. راجع الأوامر والمراكز والقرار المسجل. شغّل عدة خطوات لتجربة التنفيذ الجزئي.
7. جرّب وقف الخسارة وجني الربح والمتابعة والخروج المرحلي مع أكثر من عقد. جرّب الإيقاف الطارئ والانقطاع وفقد الاستجابة ثم المصالحة المحلية؛ الحالة المجهولة تمنع دخولًا جديدًا.
8. التعزيز والانعكاس اختياريان ومعطلان افتراضيًا. يحتاج الانعكاس إغلاقًا كاملًا وإشارة معاكسة حديثة؛ الإغلاق الجزئي أو فشله لا يجيز فتح الاتجاه الآخر.
9. افتح مختبر الرسوم: Wave وClassic وHarmonic وIndicator وAI Confluence. جرّب التكبير والتحريك والطبقات ومؤشر Replay. المخرجات البحثية اصطناعية ولا تمنح صلاحية أمر.
10. افتح صفقة تاريخية لمراجعة أدلتها المسجلة، وجرّب التقارير والاختبار التاريخي. أسباب الصفقات القديمة غير المسجلة لا تُختلق. أغلق التطبيق وافتحه للتحقق من الحفظ على هاتفك، ثم جرّب الداكن والفاتح ووضع النظام.

زمن Demo يتوقف عند إغلاق التطبيق أو دخوله الخلفية. هذا متوقع للمحاكاة المحلية. لا يعتمد عامل الخادم على الهاتف عندما يُشغّل لاحقًا. لا تنتقل بيانات Demo تلقائيًا إلى Backend أو Paper أو Live.

التوقيع الحالي للمعاينة مؤقت بين تشغيلات CI؛ عند إصدار Preview لاحق بشهادة أخرى لا تحذف النسخة السابقة وبياناتها. التوقيع الثابت يحتاج إعدادًا آمنًا منفصلًا وفق `DEVELOPMENT_SIGNING.md`. الحد الأدنى Android 7.0 / API 24 وفق ملف APK المتحقق، ويدعم arm64 وarmv7 وx86_64؛ لم يُختبر التثبيت على هاتف فعلي خلال هذه المهمة.

## المصدر واختبارات Python

فك ZIP في مجلد جديد أو استنسخ الفرع الخاص `develop/v1.0`. حزم التاريخ في `repository/` اختيارية للاستعادة، وليست مطلوبة للتشغيل. لا تنسخ ملفات `.env` أو قواعد بيانات من مشاريع أخرى.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r backend/requirements.lock
pip install --no-deps -e './backend[test]'
python -m pytest backend/tests -q
python scripts/security_scan.py --repository .
```

## خادم Mock اختياري على الحاسوب

ولّد رمز API عشوائيًا محليًا، ولا ترسله في المحادثة. أبقِ منفذ الخدمة على loopback. من جذر المشروع:

```bash
export OPTIONS_API_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export DATABASE_URL="sqlite:///$PWD/options_demo.db"
export TRADING_MODE=paper BROKER_PROVIDER=mock ENABLE_LIVE=false
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

في طرفية ثانية بنفس بيئة المشروع ومتغيراته، شغّل العامل للتحليل فقط:

```bash
python -m app.worker --interval 30
```

ولتنفيذ Mock الاصطناعي عند تفعيل إعدادات الحساب ومصالحتها:

```bash
python -m app.worker --execute-mock --interval 30
```

`paper` في هذا الخادم اسم وضع المحاكاة القديم، **وليس IBKR Paper**. لا يوجد وسيط متصل. بعد تشغيل Repository تصبح حالة الحسابات مجهولة حتى المصالحة الصريحة؛ تتطلب المراكز علامات خيارات حديثة ومشاهدة سوق اصطناعية متاحة قبل دخول جديد. `/health` لسلامة العملية، و`/api/readiness` محمي لسلامة القاعدة والعامل؛ لا يكفي أي منهما وحده لقبول صفقة.

## Docker وPostgreSQL

ولّد `POSTGRES_PASSWORD` و`OPTIONS_API_TOKEN` محليًا، واحفظهما في `infra/.env` بصلاحية `0600` خارج Git. ثم:

```bash
docker compose --env-file infra/.env -f infra/compose.yaml up --build -d
```

قاعدة البيانات غير منشورة إلى المضيف، وAPI على `127.0.0.1:8000`. العامل الافتراضي تحليل فقط. راجع `OPERATIONS_V1.md` للنسخ والاستعادة وHTTPS المحلي الاختياري. لا تستخدم `down --volumes` على بيانات تريد الاحتفاظ بها، ولا تعرض المنافذ للإنترنت للوصول من الهاتف. لا حاجة لأي خادم لتجربة APK محليًا.

## بناء Flutter وiOS

بيئة البناء المستخدمة في CI: Flutter 3.47.7، Java 17، Android SDK؛ وmacOS/Xcode لبناء iOS.

```bash
cd mobile
bash scripts/bootstrap.sh
flutter analyze
flutter test
flutter build apk --debug --build-name=1.0.0 --build-number=10
```

على macOS فقط:

```bash
flutter build ios --release --no-codesign --build-name=1.0.0 --build-number=10
```

يمكن تخصيص iOS Bundle Identifier عبر `IOS_BUNDLE_ID` أو مدخل workflow اليدوي. البناء غير الموقع لا يتيح TestFlight. يلزم لاحقًا حساب Apple Developer ومعرّف وشهادات وProvisioning وتوقيع وتوزيع واختبار جهاز، دون إرسال أي منها إلى المحادثة.

## Termux

APK لا يحتاج Termux. يمكن التحقق من بصمته بعد التنزيل:

```bash
pkg install coreutils
termux-setup-storage
sha256sum ~/storage/downloads/options-ai-trader-v1.0.apk
```

قارن الناتج بالدليل المرفق. لم تُشغّل الاختبارات داخل Termux؛ بناء Flutter/Android هناك ليس مسار البناء المعتمد لهذا الإصدار. استخدم GitHub Actions أو بيئة تطوير مدعومة. المصدر وتقارير الاختبارات يحددان النتائج الفعلية بدل افتراض نجاح البناء من وجود ملفات الإعداد.
