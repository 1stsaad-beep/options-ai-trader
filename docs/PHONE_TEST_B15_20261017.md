Reproduce: `OAT_PAPER_TEST_BUILD` is set by `mobile/scripts/build_paper_test.sh 24 1.0.0-papertest.b15 papertest-b15 <out>`. The script builds, then checks the actual APK with `aapt` and `apksigner` through `verify_paper_test_identity.py`, which checks the id, versionCode, launcher name, non-debuggability and a single certificate matching the box key. It refuses any other identity.

The identity is scoped to the `OAT_PAPER_TEST_BUILD` environment variable only. It cannot be combined with `OAT_PREVIEW_BUILD`, and CI's Build 23 identity checks (`android.yaml`, `verify_preview_identity.py`) are unchanged. No manifest provider/authority is shared, so the install cannot conflict. Android Keystore keys and app data are per-app, so this app never reads or changes Build 23 data.

## Changes in the first-run path
- On first launch the drawer of the home screen (Demo) has a top entry, «حسابات الوسطاء (Paper)». Before this, the broker accounts screen was reachable only from inside the optional server screen.
- Saving an account runs «فحص الاتصال» automatically, read-only against `paper-api.alpaca.markets`.
- An Alpaca key starting with `AK` (Live) is refused before anything is stored or sent, with a clear message.
- Pasted spaces at the ends of a key are trimmed (as before). A space inside a key is rejected.
- The Live switch is visible and greyed (`onChanged: null`).
- Paper orders still require review and then explicit confirmation (B4), and stay subject to eligibility (B9).

## قائمة اختبار الهاتف (Alpaca Paper)

قبل البدء:
- ثبّت `options-ai-trader-b15-papertest-release.apk` عبر «تثبيت تطبيقات غير معروفة».
- **لا تحذف Build 23** ولا تمسح بياناته. يظهر التطبيق الجديد باسم «Options AI Trader – Paper Test» بجانبه.
- من لوحة Alpaca في وضع **Paper Trading** فقط، أنشئ مفتاح API. يبدأ Key ID عادة بـ `PK`.

1. **فتح التطبيق:**
   - افتح القائمة الجانبية وتأكد من ظهور «نسخة اختبار Paper (papertest-b15)».
   - اختر «حسابات الوسطاء (Paper)».
   - تأكد أن مفتاح «Live Trading» رمادي ولا يمكن تشغيله.
2. **إدخال المفاتيح:**
   - «إضافة حساب» ← الوسيط Alpaca ← اسم اختياري.
   - الصق API Key ID وSecret Key، ويجب أن يظهر السر نقاطًا.
   - اضغط «حفظ مشفر».
3. **فحص الاتصال:**
   - يبدأ تلقائيًا ويجب أن تظهر «متصل (Paper) • رقم الحساب • نقد • قيمة».
   - عند ظهور HTTP 401 تحقق أن المفاتيح من Paper.
   - جرّب زر الفحص مرة ثانية.
4. **المحفظة:**
   - اضغط على الحساب. يجب أن يظهر النقد والقيمة والقوة الشرائية كما في لوحة Alpaca Paper، ثم المراكز.
   - اسحب للتحديث، ولاحظ «وقت الاستلام».
5. **أمر Paper صغير:**
   - «أمر Paper» ← عقد واحد، قريب من السعر، بسعر حد منخفض.
   - راجع الملخص ثم أكّد. بدون تأكيد لا يُرسل شيء.
   - إذا رُفض لعدم الأهلية (فارق، OI، Delta) فهذا متوقع ومسجل.
   - تحقق من ظهور الأمر في لوحة Alpaca Paper.
6. **المطابقة:**
   - اضغط «مطابقة الأوامر» وتأكد أن الحالة مطابقة للوحة Alpaca (NEW/FILLED/CANCELED).
   - إن وُجد أمر غير محسوم فالحسم اليدوي يتطلب تأكيدًا.
7. **بطاقة NAV اليومي (أسفل المحفظة):**
   - خلال جلسة السوق (نيويورك 9:30–16:00) يُسجل قيمة اليوم كقيمة مؤقتة.
   - بعد أيام تداول متتالية تظهر العوائد. يبقى Sharpe «غير متاح» حتى 20 عائدًا يوميًا دون أيام ناقصة.
8. **الأمان:**
   - أغلق التطبيق وافتحه: الحساب باقٍ، والمفاتيح لا تُعرض.
   - «أرشفة» تحذف المفاتيح فقط وتبقي السجل.
   - تأكد أن Build 23 ما زال يعمل ببياناته.

أرسل لقطات أو نص أي رسالة خطأ، ورقم الخطوة.
