## 2. تشغيل الخادم على حاسوب محلي

فك المصدر داخل مجلد مستقل. من المجلد الذي يحتوي README وbackend، استخدم Python 3.11+:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r backend/requirements.lock
python -m pip install --no-deps -e './backend[test]'
python -m pytest -q backend
python scripts/smoke_http.py
export OPTIONS_API_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
export DATABASE_URL="sqlite:///$PWD/options_demo.db"
export TRADING_MODE=paper BROKER_PROVIDER=mock ENABLE_LIVE=false
cd backend
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

أدخل `OPTIONS_API_TOKEN` الذي ولدته محليًا في التطبيق. لا ترسله في المحادثة أو تحفظه في Git أو تضمّنه في APK. يمكن فحص `http://127.0.0.1:8000/health` محليًا؛ يجب أن يظهر الإصدار 0.4.0 و`live_enabled=false` و`external_analysis_enabled=false`.

لبيئة Windows استخدم أوامر تفعيل البيئة ومتغيرات PowerShell المكافئة. الأوامر أعلاه مخصصة لشِل POSIX؛ لم تُشغّل في Windows أو Termux أثناء هذه المهمة.

## 3. توصيل الهاتف بالخادم

المسار الأسهل للتطوير المحلي هو USB مع Android platform-tools على الحاسوب:

```sh
adb devices
adb reverse tcp:8000 tcp:8000
```

فعّل USB debugging على هاتفك ووافق على الحاسوب محليًا. من زر **اتصال الخادم** داخل التطبيق أدخل:

- هاتف عبر USB reverse: `http://127.0.0.1:8000`.
- محاكي Android على الحاسوب: `http://10.0.2.2:8000`.
- خادم يعمل على الهاتف نفسه: `http://127.0.0.1:8000`.

أدخل رمز الخادم في حقل رمز الوصول. يخزن التطبيق الرمز والإعدادات في الذاكرة خلال الجلسة؛ قد تحتاج إدخالها مجددًا بعد إغلاقه. الخادم البعيد يتطلب HTTPS صالحًا؛ التطبيق يرفض HTTP بعنوان شبكة بعيد مثل 192.168.x.x. لا تنشر قاعدة البيانات أو API مباشرة على الإنترنت لأجل هذه التجربة.

## 4. تجربة من الهاتف

1. من **الحسابات** أضف حساب محاكاة؛ ينشئ التطبيق رصيدًا افتراضيًا ثابتًا قدره 10,000 دولار. لا يوجد حقل لتغييره من الهاتف حاليًا.
2. اختر الحساب، واترك الوضع **Paper / Mock**. فعّل رمز NVDA من قائمة المراقبة؛ التحقق داخل كتالوج Mock فقط. AAPL وTSLA ضمن القائمة الافتراضية، ويمكن إضافة غيرها إن دعمها الكتالوج.
3. اضغط **مصالحة حالة المحاكاة** من الحسابات بعد إعادة التشغيل أو الانقطاع.
4. حدّث ملاحظة السوق من زر **تحديث ملاحظة سوق اصطناعية** للرمز. صلاحيتها 60 ثانية؛ المصالحة وحدها لا تجدد السوق.
5. من إعدادات الاستراتيجيات فعّل breakout أو pullback والأتمتة التجريبية للحساب. جرب كمية 1 وجزء تنفيذ 1 أولًا؛ أتمتة كل حساب معطلة افتراضيًا.
6. اضغط **تشغيل دورة محاكاة واحدة**. راجع النتيجة وسبب المنع إن وجد، ثم الأوامر والمراكز وسجل القرارات.
7. لإظهار التنفيذ الجزئي الآلي استخدم حساب اختبار 30,000 دولار منشأ عبر API كما في الأمر أدناه، وكمية 3 وجزء تنفيذ 1 مع مخاطر تسمح بها. أعد التشغيل بعد ملاحظة سعر جديدة؛ تكرار الملاحظة نفسها لا يملأ جزءًا ثانيًا. الحساب الافتراضي 10,000 مع حد قسط 2% قد يرفض عقدين بسعر 1.05؛ هذا رفض مخاطر صحيح.
8. البيانات الافتراضية للخيار ثابتة عند bid=1.00 وask=1.05؛ لا ينتج عنها تحرك سوق حقيقي. لتجربة خروج مرئي فقط، يمكن ضبط وقف الخسارة مؤقتًا إلى 1%؛ سيحقق السبريد الاصطناعي شرط الوقف في الدورة التالية. راجع إلغاء بقية الشراء وإغلاق المملوك. هذا إعداد اختبار وليس توصية استراتيجية.
9. يوجد دخول آلي واحد كحد أقصى للرمز في الحساب في يوم UTC، حتى بعد الإغلاق. لسيناريو مستقل استخدم حساب محاكاة جديدًا؛ لا تتوقع إعادة الدخول كل ضغطة.
10. اختبر حسابًا ثانيًا؛ إعداداته وأوامره ومراكزه مستقلة. زر الإيقاف الطارئ يمنع فتح مراكز جديدة، ولا يضمن تصفية فورية. تظل الإغلاقات مشروطة بالملكية وحالة الحساب والأسعار.

لإنشاء حساب اختبار أكبر من طرف الخادم المحلي، مع وجود الرمز في متغير البيئة الذي ولدته:

```sh
curl --fail -X POST http://127.0.0.1:8000/api/accounts \
  -H "Authorization: Bearer $OPTIONS_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Partial Mock demo","equity_cents":3000000}'
```

حدّث قائمة الحسابات في الهاتف بعد ذلك. هذا رصيد اصطناعي لا إيداع مالي.

تفعيل الأتمتة يسمح لها بإدارة كل المراكز التجريبية المملوكة لذلك الحساب، بما فيها المفتوحة يدويًا. تعطيل الأتمتة يوقف تقدم أوامرها الآلي؛ لا يعني إلغاء كل الأوامر أو إغلاق كل المراكز. افحص الأوامر وألغِ المعلّق عند الحاجة.

## 5. العامل المستقل

الزر يشغل دورة واحدة فقط. يمكن تشغيل عامل من نافذة أخرى بعد ضبط **نفس مسار قاعدة البيانات المطلق** ومتغيرات المحاكاة:

```sh
cd backend
python -m app.worker --execute-mock --interval 30
```

بدون `--execute-mock` يعمل التحليل فقط. افتح الخادم والعامل أولًا ثم صالح الحساب من التطبيق: تهيئة Repository عند بدء أي منهما تبطل الثقة عمدًا. العامل لا يستعيد حالة مجهولة ولا يجدد السوق تلقائيًا؛ عند قدم البيانات يلزم تحديث Mock صريح. لا تعتمد على هذا الإصدار كتغذية سوق تعمل وحدها طوال اليوم. بعد سقوط الاتصال لا تكرر إرسال أمر يدوي بمفتاح جديد؛ صالح وافحص الإيصال الموجود.

## 7. Termux وDocker وiOS

لم يُختبر الخادم داخل Termux. يمكن تشغيل عميل APK مع خادم الحاسوب عبر USB كما سبق. تشغيل Python على الهاتف يحتاج بيئة Termux واعتمادياتها، وقد لا تتوفر عجلات `psycopg-binary` المقفلة لمنصة Android؛ لا يعني نجاح Linux نجاح Termux. لا ننصح بحذف الاعتماديات عشوائيًا أو تغيير محرك المخاطر لتجاوز مشكلة تثبيت. هذا مسار إضافي يحتاج تحققًا على جهاز.

لـDocker على مضيف يدعمه: انسخ `infra/.env.example` إلى `infra/.env`، وضع رمزين عشوائيين محليين ثم `chmod 600 infra/.env`:

```sh
docker compose --env-file infra/.env -f infra/compose.yaml up --build
```

لتشغيل العامل التجريبي بدل العامل التحليلي، مع بقاء تفعيل كل حساب صريحًا:

```sh
docker compose --env-file infra/.env -f infra/compose.yaml -f infra/compose.automation.yaml up --build
```

PostgreSQL بلا منفذ منشور، وAPI مربوط بـ127.0.0.1. Docker/Compose/PostgreSQL لم تُشغّل في هذه البيئة؛ اقرأ `docs/DATABASE.md` لفحص قاعدة تجريبية معزولة.

ملفات iOS موجودة؛ `.github/workflows/ios.yaml` يبني تطبيقًا غير موقع على macOS عند تشغيله لاحقًا. Bundle Identifier قابل للتخصيص. Apple Developer وApp Store Connect وشهادات التوقيع مطلوبة لـTestFlight، ولا تُرسل بياناتها في المحادثة. لم يُبنَ iOS فعليًا هنا.
