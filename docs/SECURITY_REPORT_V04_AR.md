# Options AI Trader V0.4 — تقرير الأمان

النطاق: تطوير ومحاكاة محلية فقط، بتاريخ 2026-10-10. تمت المحافظة على إصلاحات V0.3 وإضافة مراجعة واختبارات لدورة الأتمتة. لا يُعد هذا التقرير اعتمادًا لتداول الأموال أو مراجعة اختراق شاملة.

## الإصلاحات المنفذة

| المشكلة أو الخطر | المعالجة الحالية | التحقق |
|---|---|---|
| استخدام بادئات أوامر آلية عبر الطلب اليدوي | حجز `auto-e:` و`auto-x:` داخليًا؛ رفضها في مسار الخدمة/API العادي | اختبارات أمنية فعلية |
| إكمال بيع مقبول سابقًا بعد تغيير الحساب إلى shadow/analysis | إعادة فحص paper/mock عند كل تنفيذ جديد، بما فيه SELL_TO_CLOSE | اختبارات انتقال الوضع |
| اعتبار حساب ذي إعدادات أو سجل إنشاء تالف موثوقًا | رفض الدفتر وتثبيت حالة غير موثوقة؛ منع التنفيذ | اختبارات فساد JSON والرصيد والمراكز |
| تكرار الطلب أو التنفيذ بعد فقدان الرد | إيصالات ومفاتيح محفوظة وبصمة حمولة؛ لا إعادة إرسال؛ تعبئة واحدة لكل ملاحظة سعر | تكرار وانقطاع وإعادة تشغيل وتزامن |
| سباق قرارات المخاطر والدورات | معاملة واحدة للدورة وقفل قاعدة البيانات القائم؛ إعادة تحقق قبل الإرسال والتنفيذ | تزامن SQLite من اتصالين؛ PostgreSQL لم يُشغّل |
| بيع غير مملوك أو محجوز أو من حساب آخر | حجز كمية إغلاق وفحص دفتر الحساب؛ إلغاء بقية الدخول عند الخروج | عزل وحجز متزامن وإغلاق جزئي |
| تنفيذ بناء على حالة مجهولة أو بيانات قديمة | رفض عند فقد الثقة، صلاحية snapshot لمدة 120 ثانية وملاحظة السوق 60 ثانية، وعدم إصلاح الحالة تلقائيًا | انقطاع وقدم وأسعار مستقبلية وتباطؤ مزود |
| تجاوز المخاطر عبر التحليل أو API | النموذج يشرح فقط؛ واجهة الدورة تقبل `{}` دون أسعار أو أوامر؛ الخدمة صاحبة قرار المخاطر | مصادقة وحقول إضافية وAI فاشل |
| أثر حساب فاسد على إغلاق حساب مستقل سليم | عزل التعامل مع الفساد؛ استمرار الإغلاق المسموح للحساب الموثوق | اختبار مستقل ضمن الدورة والعامل |
| تسوية مراكز من العامل التحليلي الافتراضي | إزالة تغيير المراكز من Shadow؛ الانتهاء التلقائي محصور بالدورة المفعّلة والحساب الموثوق | اختبار عدم الطفرة في Shadow |

استُبدل محول التحليل الخاص السابق بـ`GenericAnalysisAdapter`. لا مسار شبكة منفذ فيه، ولا صلاحية أوامر، والتكامل الخارجي معطل. أزيلت الإشارات الخاصة من الملفات النشطة؛ يحتفظ أرشيف الإصدار السابق وتاريخ Git بالمحتوى القديم للرجوع فقط. لم تُعدّل ملفات أي مشروع آخر.

## الحدود الأمنية المحفوظة

- Live مقفل في إعدادات التشغيل والخدمة والمحولات والواجهة؛ لا طريقة تفعيل مقدمة في هذه الحزمة.
- IBKR محول هيكلي مقفل دون اتصال، وMockBroker هو مصدر التحقق والتنفيذ الوحيد.
- كل حساب يحمل إعداداته ومراقبته ومراكزه وأوامره؛ توجد حدود للمجموعات والمشرف العالمي.
- فتح مراكز جديدة يخضع للمصالحة والرصيد والأوامر القائمة والمخاطر. الإيقاف الطارئ لا يبيع تلقائيًا دون شروط؛ يسمح بإغلاق المملوك فقط مع حساب موثوق وأسعار صالحة.
- `/api/*` و`/docs` و`/openapi.json` تتطلب رمزًا محليًا. إعدادات Compose تنشر API على 127.0.0.1 فقط؛ لا منفذ منشور لقاعدة البيانات.
- التطبيق لا يحفظ الرمز على القرص ولا يتبع تحويلات HTTP التي قد تسربه، ويقصر HTTP غير المشفر على عناوين التطوير المحلية المحددة. لا أسرار ضمن المصدر أو APK.
- مفاتيح التوقيع وملفات البيئة وقواعد البيانات المحلية والكاش وأدوات البناء لا تُضاف لحزمة المصدر.

## الأدلة الفعلية

المجموعة الكاملة: **185 Python ناجحًا، صفر فشل أو تجاوز**؛ منها 36 اختبار مراجعة أمنية مستقلة ناجحًا. Flutter: **24 ناجحًا** وAnalyze دون مشاكل. راجع تقرير الاختبارات للأوامر والملفات؛ لا تجمع الأعداد الفرعية مرتين.

## النواقص والمخاطر المتبقية

1. النظام شخصي برمز وصول واحد؛ عزل حسابات التداول ليس نظام هويات متعدد المستخدمين. لا RBAC أو rate limiting أو إدارة أسرار إنتاجية أو تدقيق غير قابل للتعديل.
2. لا فحص اختراق خارجي أو فحص ثغرات اعتماديات جديد في V0.4. `pip check` يختبر اتساق المتطلبات، ولا يكشف الثغرات.
3. اختبارات PostgreSQL/Compose والتزامن متعدد العمليات عليهما لم تُشغّل. إعداد قاعدة التطوير ليس إعداد صلاحيات إنتاجية نهائيًا.
4. بيانات الحساب والرصيد والأسعار محلية مصطنعة؛ المصالحة لا تتحقق من وسيط. لا مصالحة مالية خارجية، ولا اتصال IBKR Paper.
5. البيانات الافتراضية ثابتة ولا يوجد بث مستمر؛ الانقطاع أو التقادم يمنع الخروج المسعر أيضًا. وقف الخسارة قاعدة قرار وليس ضمانًا لسعر أو خروج أثناء انقطاع التغذية.
6. الخسارة اليومية والتعرض بالقيمة الدفترية؛ التقييم السوقي المتكامل للأرباح غير المحققة ما زال ناقصًا. تنفيذ المحاكاة الآلي لا يضيف رسومًا وانزلاقًا فوق السبريد.
7. انتهاء العقد تسوية تحفظية بخسارة القسط؛ لا ممارسة أو تعيين أو تسوية وسيط. لا تقويم جلسات أو تنفيذ سياسة زمنية مختلفة لـintraday/swing.
8. APK تجريبي بتوقيع تطوير؛ لا هاتف فعلي اختُبر. اختلاف مفتاح توقيع V0.3 قد يمنع التحديث المباشر. لا بناء iOS أو توقيع متجر.

لا توجد نتيجة اختبار تبرر إزالة قفل Live. تبقى المرحلة التالية محصورة في محاكاة أكثر واقعية وفحوص المنصة وقاعدة البيانات.
