# مراجعة أساس الأمان وخطة التحقق لـV1

التاريخ: **2026-10-10**. المرجع: V0.5 عند `ccd1d2c181de3968e9042ce7c1435571c1f3301a`.

هذه مراجعة قبل تعديل التنفيذ، وليست شهادة اجتياز أمني للإصدار النهائي. النتائج أدناه تصف خط الأساس المقروء؛ أي إصلاحات V1 واختباراتها يجب أن تظهر في تقرير الإصدار بأدلتها الفعلية.

## أعمال نُفذت فعليًا في هذه المراجعة

- قراءة metadata للمستودع بواسطة GitHub المتصل: `visibility=private`، وصلاحيات `pull/push/admin` متاحة، والمستودع غير مؤرشف. هذه قراءة صلاحيات، وليست اختبار كتابة جديدًا.
- قراءة ملفات API والخدمة وRepository وWorker وAdapters وDocker/Compose وCI والتوقيع وعميل Flutter وحفظ Demo وملفات الاعتماديات وتقارير V0.5.
- فحص أسماء الملفات المتتبعة و205 ملفات نصية قابلة للقراءة بحثًا عن أنماط عالية التحديد لمفاتيح private key وGitHub وAWS access key وOpenAI API key. **0 تطابق** في هذه الأنماط، و0 ملف متتبع بأسماء `.env` أو امتدادات `.jks/.keystore/.p12/.pfx/.key`.
- فحص إشارات التكامل القديم في الملفات النشطة: لا إشارة لاتينية إلى اسم المشروع الآخر؛ التطابقات العربية الأولية كانت أجزاء كلمات مثل «موجود» و«موجبة»، وليست تكاملًا. لا تُحذف هذه الكلمات الطبيعية.

لم يشمل هذا الفحص المحدود فك كل binary أو تاريخ كل commit أو جميع صيغ الأسرار؛ لم يُشغَّل خلال هذه المراجعة scanner ثغرات خارجي أو اختبار اختراق. نجاح فحص أنماط لا يثبت غياب الأسرار أو الثغرات.

## خصائص سليمة في V0.5 ينبغي الحفاظ عليها

| المساحة | الدليل المقروء | الحد العملي |
|---|---|---|
| Live والوسطاء | API وWorker يرفضان إعداد Live؛ إعداد الحساب يجيز mock فقط؛ `IBKRAdapter.connect/submit` يرفضان دائمًا | اختبر هذه المسارات مجددًا بعد أي إعادة تنظيم |
| التحليل الخارجي | `GenericAnalysisAdapter.enabled` ثابت false، ولا I/O خارجي أو صلاحية تنفيذ | لا يكفي تغيير flag لتفويض مزود خارجي |

| عزل الحساب | تمرير account_id صراحةً، استعلامات SQL بمعاملات، تقييد اسم الجدول، علاقات DB واختبارات تاريخية | لا تخلط العزل المالي مع صلاحيات المستخدمين |
| التزامن | transaction واحدة للتغييرات، RLock في العملية، PostgreSQL advisory transaction lock، SQLite BEGIN IMMEDIATE | قفل عالمي محافظ؛ اختبر التنافس بين اتصالات مستقلة قبل تحسين الأداء |
| استعادة الثقة | بدء Repository يبطل `state_known`، والتحقق من عمر لقطة الحساب والسوق قبل الدخول | بدء عامل جديد قد يقفل حسابات مستخدمة؛ يجب أن يبقى السلوك معلنًا |
| عميل الهاتف | يرفض HTTP البعيد وuserinfo وإعادة التوجيه، مهلة 12 ثانية، لا retry تلقائي للأوامر | الخادم الذي يدخله المالك سيستقبل token؛ لا persistence آمن للأسرار حاليًا |
| Demo | دفتر اصطناعي مستقل، حفظ snapshot واحد، فشل التحميل لا يمحو البيانات، فشل الحفظ يرجع الحالة ويوقف المؤقت | SharedPreferences ليست مخزن معاملات أو حماية من تعديل جهاز مخترق |

| متوسطة | token إداري واحد يرى ويعدل جميع الحسابات | مقبول فقط لخادم شخصي محمي؛ لا تسمِّه multi-tenant. أي توسع لمستخدمين يتطلب ownership/scopes وصلاحيات server-side |

| متوسطة | `/health` يُرجع ok دائمًا دون فحص قاعدة البيانات أو worker | افصل liveness عن authenticated readiness؛ أظهر DB/worker freshness وحالة القفل دون كشف تفاصيل حساسة |
| متوسطة | الاعتماديات Python مثبتة بالإصدار بلا hashes، وbuild dependency `setuptools>=68` غير مثبتة، وActions تستخدم tags متحركة | سجل SBOM وإصدارات الأدوات، شغّل audit، وثبت Actions إلى commits موثقة؛ لا ترفع إصدارًا عشوائيًا دون إعادة الاختبارات |
| متوسطة | صور Python/PostgreSQL tags متحركة، لا scan صورة موثق | سجل digest وافحص الصورة إن أمكن؛ حدّث عبر تغيير قابل للمراجعة |
| متوسطة | لا backup/restore تمرين موثق للبيانات والأحداث | backup محلي آمن خارج Git، تحقق hash واختبار restore إلى قاعدة جديدة، ثم إعادة مصالحة؛ لا تستعيد حالة trusted مباشرة |
| متوسطة | ملف `.dockerignore` محدود مقارنة بـ`.gitignore` | استبعد key/cert/env/backups/reports الحساسة من build context حتى إن لم تُنسخ داخل الصورة |
| متوسطة | مفتاح تطوير V0.5 كان محليًا خارج Git | تحقق من توافر نفس المفتاح دون طباعته. إن تعذر استرداده لا يمكن إعادة إنشاء توقيع مطابق من certificate؛ أفصح عن تغير الهوية ومتطلبات التثبيت واحفظ مفتاحًا جديدًا فقط عبر آلية آمنة مصرح بها |
| متوسطة | backtests وDemo اصطناعية مبسطة | لا دليل ربحية أو تكافؤ تنفيذ IBKR؛ أبقِ المحركات التجريبية Shadow وبياناتها مميزة |

## بوابات تحقق الإصدار

هذه قائمة إجراءات مطلوبة؛ الحالة **لم تُنفذ ضمن هذه المراجعة** ما لم يورد تقرير الإصدار log جديدًا:

1. **المصدر والتاريخ:** فحص الأسرار في الفرق الجديد والشجرة وتاريخ Git المتاح باستخدام أداة مناسبة؛ عدم إرسال القيم المكتشفة إلى logs؛ مراجعة `.env.example` وtest fixtures يدويًا بدل تجاهل كل النتائج آليًا.
2. **الاعتماديات:** تشغيل `pip-audit` ضد lock وبيئة التثبيت الفعلية، حفظ JSON وexit code؛ فصل تعذر جلب advisories عن نجاح scan. فحص حزم Dart/Gradle وGitHub advisories بما تسمح الأدوات، وعدم مساواة `pub outdated` بفحص CVE.
3. **SAST:** تشغيل فحص Python، مراجعة كل finding حسب السياق، وحفظ السبب لأي suppression. فحص shell/CI خصوصًا interpolation ومدخلات workflow والأسرار والرفع إلى artifacts.
4. **حدود API:** فشل missing/invalid/Unicode bearer، منع extra fields والأنواع غير الصحيحة، حساب غير موجود، ربط order من حساب آخر، حالات DB failure وoversized payload، عدم ظهور token أو credential في الأخطاء.
5. **دفتر الأوامر:** duplicate request/content conflict، duplicate fill وتصحيح/تأخر حدث، concurrent admission، lost submit/cancel response، restart/reconcile، reserved exposure، no oversell، lock الاتجاه المعاكس، reversals بلا فتح مبكر، scaling cooldown/idempotency.
6. **المخاطر:** حسابات أربعة على الأقل مع عدد غير ثابت؛ account/group caps، خفض الإعدادات أثناء pending/partial، allocation=0، حدود مرتفعة بإقرار منفصل، سعر/رصيد قديم أو في المستقبل، market outage، emergency stop مع قدرة إغلاق المملوك بعد عودة الثقة.
7. **السببية:** حفظ Decision Snapshot قبل التنفيذ، اختبار نتائج كل prefix دون تغيير السجل القديم، تأكيد pivots له وقت اكتشاف مستقل، تكاليف/انزلاق/سبريد، walk-forward خارج فترة المعايرة، وcounterfactual معلن وليس إعادة كتابة السبب.
8. **الهاتف:** `flutter analyze` وwidget/unit tests، Demo بلا أي HTTP، حفظ واستعادة وتلف snapshot، lifecycle pause، RTL/light/dark/system وأحجام شاشات مختلفة، عدم انتقال Demo إلى backend.
9. **قاعدة البيانات:** PostgreSQL فعلي لترحيلات upgrade وFK وrollback والتنافس عبر أكثر من اتصال؛ تسليم تعداد pass/fail/skip منفصل عن SQLite. لا تستخدم قاعدة مستخدم حقيقية لاختبارات الحذف.
10. **المخرجات:** manifest/APK version، SHA256، تحقق signature وشهادة التوقيع؛ iOS unsigned يظل غير صالح لـTestFlight؛ لا claim لتثبيت جهاز دون تنفيذه.

## حد التفويض الحالي

يجوز التطوير والاختبار الاصطناعي وCI ضمن المستودع الخاص الحالي. لا يجوز الاتصال بحساب IBKR حتى Paper، أو تفعيل Live، أو طلب كلمات مرور/OTP داخل المحادثة، أو شراء استضافة/بيانات/API، أو تغيير ملفات مشروع آخر. هذه الحدود لا تتغير بنجاح الاختبارات أو ارتفاع System Trust Score.
