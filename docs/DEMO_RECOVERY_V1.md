## الخلل المثبت والنطاق

كان فشل فك الحفظ عند أول فتح يعطل قائمة الاستيراد بالكامل، رغم توفر نسخة Demo سليمة لدى المستخدم. وكان فقد الحفظ بعد قراءة سابقة قد يؤدي إلى إنشاء حسابات افتراضية جديدة. الكود الجديد يتيح استردادًا صريحًا ويحظر إنشاء بديل تلقائي بعد وجود أصل معروف.

لا يحاول إصلاح نص تالف أو اختلاق صفقات ونتائج. قد يكون النص غير قابل للقراءة لأنه من إصدار أحدث، لا لأنه تالف؛ تبقى نسخته الأصلية محفوظة كما هي. جميع مبالغ وأسعار Demo اصطناعية، ولا يوجد اتصال بوسيط أو مصدر مالي.

## مسار الاسترداد

1. عند تعذر فتح الحفظ، استخدم **نسخ النص الأصلي غير المقروء إلى الحافظة** واحفظه محليًا. هذه عملية صريحة، وليست قراءة تلقائية للحافظة أو إنشاء ملف. النص الخام ليس بالضرورة نسخة قابلة للاستيراد.
2. اختر **استرداد من نسخة Demo محفوظة**، والصق نسخة JSON سبق تصديرها من التطبيق. يُطبق نفس فحص الحجم (2 MiB)، والإصدار، والحقول، والدفتر، ومنع نقل إعدادات الاتصال/الاعتماديات السرية المستخدم في الاستيراد العادي.
3. راجع أسماء الحسابات والأعداد، ثم ألغِ أو أكد استبدال جميع حسابات Demo. لا دمج ولا كتابة في مرحلة المعاينة.
4. قبل الاستبدال، يعيد التطبيق قراءة الأصل، ويحفظه تحت مفتاح محلي منفصل، ويتحقق من مطابقته، ثم يعيد فحص الحفظ الحالي. اختلاف الأصل أو فشل حفظه يمنع الاستبدال.
5. لا تُفتح الحسابات المستعادة إلا بعد كتابة النسخة الجديدة وإعادة قراءتها ومطابقتها. عند فشل الكتابة أو التحقق، يحاول التطبيق إعادة الأصل حرفيًا. عند تعذر التراجع تُقفل الكتابة حتى قراءة موثوقة، ويبقى الأصل متاحًا للنسخ.
6. بعد النجاح، راجع الأوامر المعلقة وصالح كل حساب قبل الاستئناف الصريح. تتوقف الأتمتة والتعزيز والانعكاس، دون تغيير حدود المخاطر أو إيصالات التنفيذ والقرارات الأصلية. لا تشغيل زمني تلقائي.
7. من قائمة النسخ يمكنك **نسخ الأصل المحتفظ به قبل الاسترداد**. تبقى هذه النسخة بعد إعادة فتح التطبيق، ولا تدخل تلقائيًا ضمن تصدير حسابات Demo الجديدة.

- إذا تعذرت قراءة التخزين نفسه، فلا نفترض وجود نص تالف معروف ولا نسمح باستبدال مجهول. أعد القراءة؛ لا تمسح بيانات التطبيق.

- نسخ النص إلى الحافظة إجراء محلي يختاره المستخدم؛ احفظه في مكان موثوق، ولا ترفعه إلى Git أو جهة خارجية. لا تشخيص عن بعد أو إرسال تلقائي.
