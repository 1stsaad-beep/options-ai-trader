# نسخ PostgreSQL واستعادته إلى قاعدة جديدة — V1.0 RC2

هذه أدوات تشغيل للمشروع الحالي، ولا تتصل بوسيط أو تعيد تشغيل التداول. لا تُشغَّل على قاعدة إنتاج تلقائيًا. لا تعني استعادة قاعدة البيانات أن حالة حساب وسيط صحيحة.

## المتطلبات

- Python واعتماد `psycopg` الموجود في متطلبات المشروع.
- `pg_dump` و`pg_restore` المتوافقان مع إصدار PostgreSQL؛ فحص CI يطلب تطابق الإصدار الرئيسي مع الخادم المؤقت.
- مجلد إخراج خاص بصلاحية `0700`، خارج Git.
- اتصال محلي محفوظ في متغير البيئة `OAT_POSTGRES_URL` أو اسم آخر تحدده `--connection-env`. لا تضع URL يتضمن كلمة مرور في سطر الأمر أو التقرير أو المحادثة.
- للنسخ: صلاحية قراءة جميع بيانات المشروع المراد نسخها. للاستعادة: دور مخصص غير superuser وله CREATEDB، دون CREATEROLE أو REPLICATION أو BYPASSRLS. لا تستخدم حساب إدارة PostgreSQL للاستعادة.

صيغة الاتصال `postgresql://USER:REPLACE_WITH_PASSWORD@HOST:PORT/DATABASE`، مع ترميز URL للرموز الخاصة. المعاملان الاختياريان الوحيدان هما `sslmode` و`sslrootcert`. الاتصال البعيد يفرض `verify-full` لفحص الشهادة واسم الخادم. محليًا فقط يمكن `disable`. لا تُقبل خدمة أو خيارات libpq حرة داخل URL. هذه السياسة لا تعد إعدادًا إنتاجيًا كاملًا للشبكة أو أدوار PostgreSQL.

## النسخ والتحقق

بعد ضبط المتغير محليًا بواسطة إدارة أسرار مناسبة:

```bash
umask 077
mkdir -p "$HOME/options-ai-trader-backups"
chmod 700 "$HOME/options-ai-trader-backups"
python scripts/postgres_backup_restore.py backup "$HOME/options-ai-trader-backups/v1-before-upgrade.dump"
python scripts/postgres_backup_restore.py verify "$HOME/options-ai-trader-backups/v1-before-upgrade.dump"
```

النسخ يستخدم snapshot متسقًا يقدمه `pg_dump`، وصيغة custom. يكتب الأرشيف وmanifest بصلاحية `0600`، ثم ينشر كل اسم ذريًا بواسطة hard link دون استبدال اسم موجود. فشل منافس في إنشاء الاسم يحافظ على الملف السابق. لا تنشر الأرشيف أو manifest في مستودع المشروع؛ يحتوي الأرشيف بيانات الحسابات التجريبية والقرارات.

الملفان منفصلان: انقطاع العملية بين نشر manifest والأرشيف قد يترك manifest يتيمًا. وجود أحدهما ليس دليل نجاح. احتفظ بالملفين، وافحصهما، واختر اسمًا جديدًا للمحاولة التالية؛ لا تحذف الملفات القديمة تلقائيًا.

التحقق ينسخ الأرشيف إلى ملف مؤقت خاص، ويطابق الحجم وSHA256، ويختبر ترويسة custom وفهرس `pg_restore --list` دون اتصال بقاعدة. يرفض الروابط الرمزية والـ manifest ذي الحقول غير المعروفة أو المكررة أو الأنواع غير الصحيحة. فحص الفهرس وحده ليس استعادة كاملة لجميع الصفوف. حد الأرشيف 50 GiB، مع حاجة لمساحة نسخة مؤقتة إضافية. الـ manifest غير موقع، والأرشيف غير مشفر؛ SHA256 يكشف فسادًا أو تغييرًا غير متوافق ولا يثبت هوية المصدر.

## الاستعادة

```bash
python scripts/postgres_backup_restore.py restore \
  "$HOME/options-ai-trader-backups/v1-before-upgrade.dump" \
  oat_restore_v1_review \
  --connection-env OAT_POSTGRES_RESTORE_URL \
  --trusted-project-archive
```

اضبط `OAT_POSTGRES_RESTORE_URL` محليًا لدور الاستعادة المحدود واتصال قاعدة صيانة يمكنه الوصول إليها؛ لا يُقرأ اسم الهدف من manifest. يجب أن يكون اسم الهدف جديدًا ويبدأ بـ `oat_restore_`. حتى قاعدة موجودة فارغة تُرفض. تُنشأ القاعدة من `template0` مع إغلاق الاتصالات، وتُسحب صلاحيات PUBLIC قبل فتحها لدور المالك. يفحص البرنامج خلوها من علاقات مستخدم ثم يستعيد داخل معاملة واحدة. لا يستخدم `--clean` أو `--create` أو تعطيل triggers، ولا يسقط قاعدة عند الفشل؛ قد تبقى القاعدة الجديدة فارغة أو بحاجة إلى فحص يدوي.

الخيار `--trusted-project-archive` إقرار بأن المصدر موثوق ومراجع، وليس فحصًا يحوّل SQL غير موثوق إلى آمن. وفق PostgreSQL، استعادة dump تنفذ شيفرة SQL يحددها مصدره. لا تستعد ملفات مجهولة، ولا تستخدم دورًا ذا صلاحيات على مشاريع أخرى. اتصال مالك آخر أو مسؤول بالخادم أثناء العملية خارج ضمان العزل لهذه الأداة؛ نفذها في بيئة مراجعة منعزلة. لا تفعل أي تبديل تلقائي لاتصال التطبيق أو worker إلى القاعدة المستعادة.

فتح القاعدة عبر `Repository` يلغي الثقة السابقة في الحسابات. افحص البيانات ثم استخدم مصالحة Mock؛ لا تعدّل `state_known` لتجاوز ذلك. في مستقبل IBKR يلزم تحقق وسيط فعلي منفصل قبل أي تداول، وهو غير مفعل هنا.

## حدود وحماية البيانات

- كلمة المرور موجودة في ذاكرة العملية وملف pgpass خاص مؤقت فقط، ولا توضع في argv أو بيئة العملية الفرعية؛ يُنظَّف الملف عند الخروج الطبيعي أو الاستثناء. الإنهاء القسري/انقطاع النظام قد يترك المجلد المؤقت الخاص ويحتاج مراجعة تشغيلية.
- لا تورث أوامر PostgreSQL رموز API أو كلمات مرور غير لازمة أو PGOPTIONS من بيئة التطبيق. أخطاء CLI عامة، وstdout/stderr أدوات PostgreSQL لا يُعرضان؛ يجب مراجعة حالات الفشل في بيئة آمنة مستقلة.
- لا تشمل النسخة أدوار الخادم وكلمات المرور وWAL المستمر وPITR أو إعدادات الخادم أو شهادات TLS. لا توجد سياسة احتفاظ آلية أو رفع سحابي أو تشفير مدمج.
- تمنع مهلة الاتصال وقفل قاعدة طويل نسبيًا توقفًا غير محدود. المهلة الكلية الافتراضية 300 ثانية؛ تقبل `--timeout` من 1 إلى 3600 ثانية.
- نجاح اختبار صغير لا يثبت RTO/RPO لقاعدة إنتاج كبيرة أو سلامة نسخ عبر إصدارات رئيسية مختلفة.

## التحقق في GitHub Actions

بعد تثبيت متطلبات Python وإتاحة عميل PostgreSQL 16، أضف خطوة بالبيئة المؤقتة نفسها المستخدمة لاختبارات PostgreSQL:

```yaml
- name: Disposable PostgreSQL backup and restore
  run: python scripts/postgres_backup_check.py > postgres-backup-restore.json
  env:
    TEST_DATABASE_ALLOW_DISPOSABLE: "1"
    TEST_DATABASE_URL: ${{ env.TEST_DATABASE_URL }}
```

في الملف الفعلي يمكن تعيين URL خدمة الاختبار محليًا للخطوة أو استخدام secret بيئي؛ لا تستعمل بيانات إنتاج. ارفع `postgres-backup-restore.json` كأثر اختبار فقط، ولا ترفع الأرشيف المؤقت. الفحص ينشئ دورًا وقاعدتين بأسماء عشوائية تخص تشغيله، ثم يزيل **هذه الموارد المؤقتة فقط**. لا يزيل قاعدة `TEST_DATABASE_URL` ولا قاعدة سابقة. أداة النسخ/الاستعادة العامة لا تسقط قواعد.

اختبارات الوحدة: `python -m pytest -q backend/tests/test_postgres_backup_restore.py`. تغطي حدود الاتصال، ملف كلمات المرور، فساد الأرشيف، سلامة manifest، عدم استبدال الملفات والقواعد، التزامن، رفض أدوار مفرطة الصلاحيات، الإقرار بمصدر SQL، فشل العميل، والتحقق من نسخة خاصة لا تتغير بتعديل الأصل. سجّل نتيجة التشغيل الفعلية منفصلة عن مجرد كتابة هذه الاختبارات.

المراجع: [pg_dump PostgreSQL 16](https://www.postgresql.org/docs/16/app-pgdump.html)، [pg_restore PostgreSQL 16](https://www.postgresql.org/docs/16/app-pgrestore.html).
