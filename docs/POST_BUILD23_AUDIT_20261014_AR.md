## المحركات البحثية: ما معنى أنها «تعمل»؟

- **Adaptive Entry / Entry Timing Optimizer:** قواعد Early/Confirmed/Pullback وتوقيت على بادئة معلومة؛ لا صلاحية تلقائية لتجاوز المخاطر أو التداول عبر وسيط.
- **Opportunity Radar / Scenario Battle:** ترتيب فرص ومقارنة سيناريوهات كمية، مع إظهار التعارض. درجاتها ليست احتمالات معايرة.
- **Option Twin:** سيناريوهات باستخدام Greeks وتكاليف في الخادم؛ لا يساوي نموذج تنفيذ Direct ولا محاسبة ممارسة أمريكية.
- **Liquidity Trap / Portfolio Correlation:** قواعد OHLCV وارتباط عوائد وتعرض بحثي؛ ليست مراقبة دفتر أوامر أو بوابة ديناميكية لكل تعبئة هاتف.
- **Decision Memory / Strategy Tournament:** لقطات أصلية ومقارنة walk-forward اصطناعية؛ ليست تعلمًا ذاتيًا يرقّي استراتيجية أو تجربة سوق مكتملة.
- **System Trust Score / Safety Supervisor:** تشخيص وبوابات أمان مستقلة؛ لا ضمان تشغيل مستمر أو ربحية، ولا سلطة LLM.

## الإصلاحات أثناء هذا التدقيق

1. الإغلاق اليدوي: كان مشروطًا بتشغيل الحساب. صار تخفيضًا صريحًا للمملوك دون تفعيل الأتمتة أو فتح الاتجاه المقابل. تغيير الإعدادات أو الانتقال للخلفية أثناء انتظار السعر يلغي الطلب؛ تبقى شروط السعر والجلسة والحفظ.
2. الوصول للمركز: زر إغلاق مستقل لكل حساب/سهم، والضغط على المركز يختار سهمه حتى بعد حذفه من قائمة المراقبة. لا يعتمد الإغلاق على اختيار صفحة سوق أخرى.
3. مصدر القرار: حفظ كامل النافذة المحدودة المستخدمة، مع العدد وأول/آخر وقت. عرض أصل محلي وشارت بمؤشر زمني؛ يحجب السبب النهائي وعلامته عند الرجوع، ويرفض مصدرًا مستقبليًا/تالفًا. السجلات القديمة تبقى جزئية؛ لا تُعاد كتابة أسبابها.
4. موجات Direct: استخدام سجل رصد/إلغاء سببي بدل إعادة عرض كل الأشكال المتطابقة، مع أساسي وبديل ودرجتين ومستويات تفعيل وإلغاء وأهداف. تُحفظ أحداث الإلغاء في snapshot v2. لا ادعاء بذاكرة مستمرة بعد إسقاط نافذة المصدر.
