# Demo V0.5 — isolated local simulator

`mobile/lib/demo/engine.dart` is pure Dart; `store.dart` supplies serialized local persistence; `screen.dart` exposes ten Arabic screens. None imports TraderApi, HTTP, sockets or a broker. `TraderApp()` opens Demo; injected TraderApi remains the original backend UI for existing tests, and an explicit separate menu opens optional Mock-server mode. No Demo data or token is transferred to it. Backend `paper` is still a synthetic Mock environment, not IBKR Paper.

The local market uses a deterministic mathematical stream and a finite 15-symbol catalog, explicitly labeled synthetic. Catalog validation is not exchange/broker entitlement verification. Account count is not hardcoded; phone resources and preferences snapshot size are practical limits. All money is integer cents, standard multiplier 100. IDs and idempotency keys are account-scoped; ownership and outstanding closing reservations are checked. A accepted-but-lost-response simulation saves the order and an unknown account state before telling the user to reconcile.

Each step uses quantitative prior/current observations, fills only orders created on an earlier tick, checks account and group limits, processes partial execution, detects stop/take exits and creates later-observation closing orders. Entry orders expire after three observations. Entries are at ask plus configured slippage; exits bid minus slippage; both pay commission. Emergency stop cancels entry remainders, permitting owned exits after reconciliation and with data available. Expiry writes cost off without exercise/assignment. The fixed synthetic UTC session is not a US exchange calendar.

Daily loss policy uses today's realized P&L plus negative open P&L conservatively; positive open P&L cannot offset losses. It is not a production mark-to-market start-of-day accounting implementation. Group limits use the strictest linked member configuration and reject uncertainty. Configurations accept only Demo and observe modes; the UI offers no Live activation. The backend independently keeps Live hard locked.

Local automation is off by default. The timer pauses when the app leaves the foreground. This mode intentionally is not a background trading service. The optional Python worker is retained for a later user-operated server.

Persistence saves one validated JSON snapshot under a dedicated preferences key. Failed writes roll back memory and stop the timer; invalid snapshots are retained and not auto-erased. Preferences are not a transactional durable financial database or encrypted secret vault: no broker credentials are stored there. Uninstalling the app/clearing its data loses Demo state. Advanced manual file tampering is outside integrity guarantees; the validation detects structural/accounting inconsistencies, not cryptographic authenticity. Orders/trades remain untruncated; diagnostics retain the most recent 2,000 events per account.

Historical Demo replay runs an independent engine instance and cannot alter active accounts. Its strategy/risk configuration is copied, synthetic prices drive sequential execution, and costs remain included. Prefix tests guard future leakage. Backend historical tests use timestamped option bid/ask observations, next-observation stop/take execution, missing valuations represented as null, and conservative expiry. Neither simulator establishes profitability, realistic liquidity or IBKR behavior.
