# B13 — Daily NAV, Sharpe and drawdown on the phone (2026-10-17)

Branch `work/nav-b13`, stacked on `work/storage-b12`. Android only, with no server changes.

## What was added
- `mobile/lib/daily_nav.dart` (`daily-nav-v1`):
  - `updateDailyNav` records one aggregate NAV value per New York session date. It records only while `paperSession(now).fill` is true, i.e. inside the regular session, using the same calendar as Market Paper.
  - Only today's record may change. Earlier dates are frozen and never rewritten or deleted.
  - An incomplete valuation (`null`) is never recorded.
  - An unchanged value causes no rewrite, so a commit that does nothing else still leaves the ledger byte-identical. `samples` counts distinct value changes.
  - History is capped at 3650 session dates. At the cap, new dates are refused; old ones are never dropped.
- `dailyMetrics` uses the rules of the server daily report (`observed_server_daily`):
  - 252 sessions per year, risk-free rate 0, sample standard deviation (ddof 1), at least 20 returns.
  - The status codes are the same: `NO_SESSIONS`, `MISSING_DAILY_VALUATION`, `INSUFFICIENT_DAILY_RETURNS`, `ZERO_RETURN_VARIANCE`, `NONPOSITIVE_RETURN_BASE`, `MODELED_DAILY_RETURNS`.
  - Max drawdown is reported in cents and as a fraction of the running peak.
- `dailyPerformance` lists every trading day between the first and last closed recorded dates. A missing trading day blocks Sharpe and drawdown with `MISSING_DAILY_VALUATION`; nothing is interpolated. Today's value is provisional and left out until the date closes.
- **Market Paper:** each `_commit` samples the account's full liquidation equity (`dailyNav` account field). It is validated in `market_paper_validation.dart`, allowed in the backup allowlist, and shown in the Direct account card (`paper-daily-nav`).
- **Broker Paper:** `DailyNavStore` saves to SecureKeyValue key `oat.brokers.nav.v1.<accountId>` and confirms the write by reading it back.
  - Each portfolio refresh samples the broker-reported `equity` with exact decimal-to-cents parsing; values with more than 2 decimals are rejected.
  - The result appears in a card at the bottom of the portfolio screen (`broker-daily-nav`). A failure never blocks the screen and shows as "unavailable".

## Evidence

- `test/daily_nav_test.dart` checks:
  - All five cases in the shared server fixture `observed_daily_v1.json`, produced by the Python/SQL daily report: status, samples, drawdown, fraction, total return and Sharpe, to within 1e-10.
  - A hand-computed Sharpe and drawdown.
  - Sampling rules (session only, frozen past days, no rewrite when unchanged).
  - A missing trading day.
  - Market Paper validation.
  - Broker store integrity, plus a widget refresh that stores 1001234 cents and contains no secret.

## Limits
- One sample per refresh or commit; there is no background sampler. Days when the app is not opened in session are missing, so Sharpe stays blocked and nothing is guessed.
- Broker NAV is whatever the broker reports as `equity`. It is not checked independently against the positions.
- Not tested on a device or with real Paper connections yet.
