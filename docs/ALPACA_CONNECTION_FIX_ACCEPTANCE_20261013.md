## سلوك الاتصال وحماية البيانات

- لا يبدأ اتصال عند فتح الصفحة أو استعادة ON أو حفظ المفاتيح. يلزم مخزن قابل للقراءة وإعداد ON ثم ضغط المستخدم «فحص الاتصال»؛ التحقق نفسه هو الذي يحدد صلاحية المفاتيح لدى المزوّد.
- المعالجة الأصلية تتحقق أيضًا من الموافقة الصريحة ووجود التطبيق في المقدمة. لا يعتمد المنع على Flutter وحده.
- لا تُنشأ هوية Keystore بديلة أثناء محاولة قراءة ملف مشفر قديم. تنسيق الملف والاسم المستعار السابقان محفوظان للتوافق داخل هوية التطبيق نفسها.
- المفاتيح داخل Android Keystore + AES-GCM، خارج النسخ الاحتياطي. التفضيلات الجديدة لا تتضمن مفاتيح. لا قيم مفاتيح في الحالة أو رسائل الخطأ أو السجلات. الهاتف المخترق أو التطبيق المعدل قد يكشفها أثناء الاستخدام؛ لا حماية مطلقة.
- أخطاء HTTP وWebSocket منفصلة؛ مثلًا WebSocket 403 يعني مصادقة مكررة، بينما HTTP 403 يخص رفض صلاحية الطلب. عند 406 يتوقف هذا التطبيق دون قطع اتصال التطبيق الآخر.
- قيود GET فقط على مضيفي بيانات Alpaca، ومنع إعادة التوجيه، ومنع واجهات أوامر Paper/Live/IBKR مستمرة. لا تغيير للاشتراك أو شراء خدمات.
- LIVE مشروط باتصال مصادق عليه ووجود شمعة دقيقة مكتملة حديثة؛ نجاح الاختبار دون شموع يعرض ذلك صراحة. الأسهم ليست بديلًا لأسعار الخيارات المؤهلة.
- ملفات Demo ومحرك Market Paper والخادم وMarket Runtime وإعدادات Oracle لم تُعدل. لا حذف لبيانات أو حسابات أو قواعد بيانات.
